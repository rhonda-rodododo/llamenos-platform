# Plan: Ed25519 Auth & Identity Purge

**Spec**: `docs/superpowers/specs/2026-05-05-ed25519-auth-purge-design.md`

## Prerequisites

- **Rust FFI Server Crypto Bridge** (Plan 1) complete — `@llamenos/crypto/ffi` available with `ed25519Sign`, `ed25519Verify`, `ed25519PubkeyFromSeed`, `sha256`
- `packages/shared/encoding.ts` available with `hexToBytes`, `bytesToHex`, `utf8ToBytes`
- No production users — zero migration risk

## Implementation Steps

### Step 1: Canonical Auth Message Format — Rust Side

**Files**:
- `packages/crypto/src/auth.rs`

**Changes**:
1. Update `create_auth_token()` message format to include pubkey:
   ```
   {LABEL_DEVICE_AUTH}:{pubkey_hex}:{timestamp_ms}:{METHOD}:{path}
   ```
   Currently uses `{LABEL_DEVICE_AUTH}:{timestamp}:{method}:{path}` — add pubkey after label
2. Update `verify_auth_token()` to match new format
3. **No pre-hashing**: Sign raw UTF-8 message bytes directly (Ed25519 internally applies SHA-512)
4. Add cross-language test vectors: specific seed → pubkey → timestamp → method → path → expected signature bytes
5. Export test vector constants for use in TypeScript integration tests

**Verification**: `cargo test --manifest-path packages/crypto/Cargo.toml` — auth tests pass with new format

---

### Step 2: Server Auth Verification — Single Ed25519 Path

**Files**:
- `apps/worker/lib/auth.ts`

**Changes**:
1. Remove entire Schnorr verification path (try-Schnorr-then-Ed25519 ladder)
2. Remove imports: `schnorr` from `@noble/curves/secp256k1.js`, `ed25519` from `@noble/curves/ed25519.js`, `sha256` from `@noble/hashes/sha2.js`, `hexToBytes`/`utf8ToBytes` from noble utils
3. Add imports: `ed25519Verify` from `@llamenos/crypto/ffi`, `hexToBytes`/`utf8ToBytes` from `@shared/encoding`, `LABEL_DEVICE_AUTH` from `@shared/crypto-labels`
4. Rewrite `verifyAuthToken()`:
   ```typescript
   const message = utf8ToBytes(
     `${LABEL_DEVICE_AUTH}:${auth.pubkey}:${auth.timestamp}:${method}:${path}`
   )
   return ed25519Verify(hexToBytes(auth.pubkey), message, hexToBytes(auth.token))
   ```
5. Keep session token (WebAuthn) auth path unchanged — it doesn't use Schnorr
6. Keep the 5-minute freshness window validation unchanged

**Verification**: `bun run typecheck` passes

### Step 4: Test Infrastructure — Ed25519 Auth Tokens

**Files**:
- `tests/api-helpers.ts`
- `tests/global-setup.ts`

**Changes**:
1. In `tests/api-helpers.ts`:
   - Remove `schnorr.sign()` import and usage
   - Import `ed25519Sign`, `ed25519PubkeyFromSeed` from `@llamenos/crypto/ffi`
   - Import `utf8ToBytes`, `bytesToHex`, `hexToBytes` from `@shared/encoding`
   - Rewrite `createAuthToken(seed, method, path)`:
     ```typescript
     const pubkey = ed25519PubkeyFromSeed(seed)
     const timestamp = Date.now()
     const message = utf8ToBytes(
       `${LABEL_DEVICE_AUTH}:${bytesToHex(pubkey)}:${timestamp}:${method}:${path}`
     )
     const token = ed25519Sign(seed, message)
     return { pubkey: bytesToHex(pubkey), timestamp, token: bytesToHex(token) }
     ```
2. In `tests/global-setup.ts`:
   - Replace nsec-based admin bootstrap with Ed25519 seed (32 bytes of zeros or deterministic test seed)
   - Use `ed25519PubkeyFromSeed()` to derive admin pubkey

## Risk Notes

- Auth message format change means ALL clients must update simultaneously — but no production users, so this is safe
- Cross-language test vectors (Rust ↔ TypeScript) are critical — a single byte mismatch in message construction breaks all auth
- Session token (WebAuthn) auth is NOT affected — it's a separate code path
