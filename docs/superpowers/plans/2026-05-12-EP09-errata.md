# EP09 Plan Errata — Self-Review Findings

> **For executing agents:** Read this BEFORE executing any EP09 plan. These are corrections and missing items discovered during spec/plan cross-review. Fix each issue as you encounter the relevant task.

## Spec Fixes (already applied to spec)

The spec was updated to fix 12 issues from self-review. Key changes:
- Delay timer starts at Signal verification, not session creation (`expiresAt` set in `POST /initiate/verify`)
- Sigchain links clarified: per-user sigchain with cross-referencing `recovery-group-accept` links from share holders
- Recovery device sigchain entry is self-authorizing (`recovery-device-add` link type)
- `userIdentifier` mapped to pubkey via HMAC blind indexes (zero-knowledge maintained)
- Duress detection mechanism specified (check share against both real and duress commitments)
- `POST /session/:id/emergency` endpoint added (9 endpoints total, was 8)
- Colluding threshold risk acknowledged in adversarial scenarios
- `RECOVERY_SALT` existing label clarified as unrelated (PIN-based recovery)

## Critical Plan Gaps (must fix during execution)

### P2 Backend — Missing Endpoints

**1. GET /sessions list endpoint**
P3 Task 2 calls `GET /recovery-group/sessions?hubId=${hubId}` but P2 only defines `GET /session/:id`. Add:
```typescript
// In recovery-group route file
authenticated.get('/sessions',
  requirePermission('recovery:view'),
  async (c) => {
    const hubId = c.req.query('hubId')
    const sessions = await services.recoveryGroup.listSessions(hubId)
    return c.json(sessions)
  }
)
```
Add `listSessions(hubId)` to RecoveryGroupService.

**2. GET /user-envelope/:hubId endpoint**
P3 Task 5 completion flow calls `GET /api/recovery-group/user-envelope/${hubId}` but no such endpoint exists. Add:
```typescript
// Unauthenticated — the recovering device uses session-scoped access
public.get('/user-envelope/:hubId',
  async (c) => {
    const { hubId } = c.req.param()
    const sessionId = c.req.query('sessionId')
    // Validate session is completed + belongs to this user
    const envelope = await services.recoveryGroup.getUserEnvelope(sessionId, hubId)
    return c.json({ envelope })
  }
)
```

**4. Session completion transition**
No code transitions session from `active` to `completed`. The recovering device needs to call an endpoint or the server detects completion when the new device authenticates with a valid recovery sigchain link.

### P2 Backend — Missing Business Logic

**5. Group rotation must re-wrap user envelopes**
Spec D13 step 3c: "Update all user recovery envelopes (re-wrap under new pubkey)." The `enrollHub`/rotation method must fetch all `user_recovery_envelopes` for the hub and re-wrap them. This requires the rotating admin to have access to each user's PUK seed (they decrypt with old group key, re-encrypt with new). Add a `rotateGroup(hubId, newConfig, oldPrivateKeyHex)` method.

**6. Audit log entry on recovery completion**
Spec line 334: "Recovery event logged to hash-chained audit log." Add audit entry creation in the completion flow.

### P1 Crypto — Type Mismatch

**7. UniFFI return type for keypair**
P1 Task 6 returns `Vec<String>` from `mobile_recovery_group_generate_keypair`. P4 iOS/Android expects a named struct (`RecoveryGroupKeypair` with `publicKeyHex`/`privateKeyHex` fields). Fix in P1: define a UniFFI Record:
```rust
#[derive(uniffi::Record)]
pub struct RecoveryGroupKeypair {
    pub public_key_hex: String,
    pub private_key_hex: String,
}
```

**8. UniFFI Share type for mobile**
P1 Task 6 passes `Vec<Share>` to `mobile_shamir_combine`. P4 iOS/Android passes JSON strings. Fix: either make `Share` a UniFFI Record (preferred) or change FFI to accept/return JSON. Preferred approach — make `Share` a UniFFI Record:
```rust
#[derive(uniffi::Record)]
pub struct ShamirShare {
    pub x: u8,
    pub y_hex: String,
}
```

### P3 Desktop — Missing Flows

**9. User auto-enrollment**
Spec lines 269-274: client auto-wraps PUK seed when authenticating to a hub with an active recovery group. No plan implements this trigger. Add to the auth/hub-join flow in the desktop client (check for recovery group, verify sigchain, wrap PUK seed, store envelope).

**10. Sigchain verification before enrollment**
Spec D9: users verify recovery group pubkey from sigchain before allowing auto-enrollment. Share holders verify sigchain link before accepting shares. No plan implements either verification. Add checks in the enrollment and auto-enrollment flows.

**11. Desktop completion flow references undefined functions**
P3 Task 5 line 1702 calls `hpkeOpenKeyFromState` and `pukUnwrapSeedFromState` — these don't exist in `platform.ts`. Add IPC commands or use existing HPKE functions with the recovery group private key.

**12. Sigchain entry for recovered device**
Spec line 331: new device creates `recovery-device-add` sigchain entry. No plan implements this. Add to P3 Task 5 completion flow and P4 Tasks 7/13.

### P3 Desktop — Type Mismatches with P2

**13. Schema property names don't match client types**
- P2 schema: `groupPublicKey` → P3 client: `publicKey` — use `groupPublicKey` everywhere
- P2 schema: `shareHolderLiveness` → P3 client: `shareHolders` — use `shareHolderLiveness`
- P2 schema: `shareCommitments` → P3 client: `commitments` — use `shareCommitments`

**14. IPC mock label IDs**
P3 Task 1.3 maps recovery labels to IDs 60-63, but P1 Task 1 uses indices 69-72. Update mock to use 69-72.

### P4 Mobile — Missing Sections

**15. Recovery status in mobile security settings**
Spec lines 547-549 require per-hub recovery status in user security settings. P3 Task 6 covers desktop. P4 does not have iOS/Android equivalent. Add read-only status views to both platforms.
