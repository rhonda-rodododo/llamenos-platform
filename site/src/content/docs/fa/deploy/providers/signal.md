Llámenos از پیام‌رسانی Signal از طریق پل self-hosted [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api) پشتیبانی می‌کند. Signal قوی‌ترین تضمین‌های حریم خصوصی را در میان همه کانال‌های پیام‌رسانی ارائه می‌دهد که آن را برای سناریوهای حساس پاسخ به بحران ایده‌آل می‌کند.

## پیش‌نیازها

- یک سرور یا VM لینوکس برای پل (می‌تواند همان سرور Asterisk باشد یا جداگانه)
- Docker نصب شده روی سرور پل
- یک شماره تلفن اختصاصی برای ثبت نام Signal
- دسترسی شبکه از پل به سرور Llámenos شما

## معماری

![معماری پل Signal](/diagrams/signal-bridge.svg)

پل signal-cli روی زیرساخت شما اجرا می‌شود و پیام‌ها را از طریق webhookهای HTTP به سرور شما ارسال می‌کند. این بدان معناست که شما کل مسیر پیام از Signal تا برنامه خود را کنترل می‌کنید.

## ۱. استقرار پل signal-cli

کانتینر Docker signal-cli-rest-api را اجرا کنید:

```bash
docker run -d \
  --name signal-cli \
  --restart unless-stopped \
  -p 8080:8080 \
  -v signal-cli-data:/home/.local/share/signal-cli \
  -e MODE=json-rpc \
  bbernhard/signal-cli-rest-api:latest
```

## ۲. ثبت نام شماره تلفن

پل را با یک شماره تلفن اختصاصی ثبت کنید:

```bash
# درخواست کد تأیید از طریق SMS
curl -X POST http://localhost:8080/v1/register/+1234567890

# تأیید با کدی که دریافت کردید
curl -X POST http://localhost:8080/v1/register/+1234567890/verify/123456
```

## ۳. پیکربندی ارسال webhook

پل را برای ارسال پیام‌های ورودی به سرور خود تنظیم کنید:

```bash
curl -X PUT http://localhost:8080/v1/about \
  -H "Content-Type: application/json" \
  -d '{
    "webhook": {
      "url": "https://your-domain.com/api/messaging/signal/webhook",
      "headers": {
        "Authorization": "Bearer your-webhook-secret"
      }
    }
  }'
```

## ۴. فعال‌سازی Signal در تنظیمات مدیر

به **تنظیمات مدیر > کانال‌های پیام‌رسانی** بروید (یا از جادوگر راه‌اندازی استفاده کنید) و **Signal** را روشن کنید.

موارد زیر را وارد کنید:
- **Bridge URL** — آدرس پل signal-cli شما (مثلاً `https://signal-bridge.example.com:8080`)
- **Bridge API Key** — یک توکن bearer برای احراز هویت درخواست‌ها به پل
- **Webhook Secret** — رازی که برای اعتبارسنجی webhookهای ورودی استفاده می‌شود (باید با آنچه در مرحله ۳ پیکربندی کردید مطابقت داشته باشد)
- **Registered Number** — شماره تلفن ثبت شده با Signal

## ۵. تست

یک پیام Signal به شماره تلفن ثبت شده خود ارسال کنید. مکالمه باید در برگه **مکالمات** ظاهر شود.

## نظارت بر سلامت

Llámenos سلامت پل signal-cli را نظارت می‌کند:
- بررسی‌های سلامت دوره‌ای به endpoint `/v1/about` پل
- تخریب تدریجی اگر پل در دسترس نباشد — کانال‌های دیگر به کار خود ادامه می‌دهند
- هشدارهای مدیر زمانی که پل از کار می‌افتد

## رونویسی پیام صوتی

پیام‌های صوتی Signal می‌توانند مستقیماً در مرورگر داوطلب با استفاده از Whisper سمت کلاینت (WASM از طریق `@huggingface/transformers`) رونویسی شوند. صدا هرگز دستگاه را ترک نمی‌کند — رونویسی رمزنگاری شده و در کنار پیام صوتی در نمای مکالمه ذخیره می‌شود. داوطلبان می‌توانند رونویسی را در تنظیمات شخصی خود فعال یا غیرفعال کنند.

## نکات امنیتی

- Signal رمزنگاری انتها به انتها بین کاربر و پل signal-cli را فراهم می‌کند
- پل پیام‌ها را برای ارسال به عنوان webhook رمزگشایی می‌کند — سرور پل به متن ساده دسترسی دارد
- احراز هویت webhook از توکن‌های bearer با مقایسه زمان ثابت استفاده می‌کند
- پل را در همان شبکه سرور Asterisk خود نگه دارید (در صورت وجود) برای حداقل قرار گرفتن در معرض
- پل تاریخچه پیام‌ها را به صورت محلی در Docker volume خود ذخیره می‌کند — رمزنگاری در حالت استراحت را در نظر بگیرید
- برای حداکثر حریم خصوصی: هر دو Asterisk (صدا) و signal-cli (پیام‌رسانی) را روی زیرساخت خود میزبانی کنید

## عیب‌یابی

- **پل پیام‌ها را دریافت نمی‌کند**: بررسی کنید که شماره تلفن به درستی با `GET /v1/about` ثبت شده است
- **شکست‌های تحویل webhook**: بررسی کنید که آدرس webhook از سرور پل قابل دسترسی است و هدر authorization مطابقت دارد
- **مشکلات ثبت نام**: برخی شماره تلفن‌ها ممکن است ابتدا باید از یک حساب Signal موجود جدا شوند
