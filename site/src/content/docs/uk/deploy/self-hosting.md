Llamenos створено для роботи на вашій власній інфраструктурі. Самостійний хостинг дає вам повний контроль над розташуванням даних, ізоляцією мережі та вибором інфраструктури — критично важливо для організацій, які захищаються від добре фінансованих противників.

## Варіанти розгортання

| Варіант | Найкраще для | Складність | Масштабування |
|---------|--------------|------------|---------------|
| [Docker Compose](/docs/en/deploy/docker) | Один сервер, рекомендований старт | Низька | Один вузол |
| [Kubernetes (Helm)](/docs/en/deploy/kubernetes) | Оркестрація багатьох служб | Середня | Горизонтальне (багато реплік) |
| [Co-op Cloud](/docs/en/deploy/coopcloud) | Кооперативні хостингові колективи | Низька | Один вузол (Swarm) |

## Файли Docker Compose

Docker Compose використовує багатошаровий підхід:

| Файл | Призначення |
|------|-------------|
| `deploy/docker/docker-compose.yml` | Базова конфігурація — всі служби, мережі, томи |
| `deploy/docker/docker-compose.production.yml` | Продуктивне накладання — TLS через Let's Encrypt, ротація журналів, обмеження ресурсів, сувора CSP |
| `deploy/docker/docker-compose.dev.yml` | Накладання для розробки — відстеження файлів, відкриті порти |
| `deploy/docker/docker-compose.ci.yml` | Накладання для CI — детерміноване тестове середовище |

Для **локальної розробки** використовуйте накладання для розробки. Для **продукції** використовуйте продуктивне накладання:

```bash
# Локально (лише служби підтримки + bun run dev:server)
docker compose -f deploy/docker/docker-compose.dev.yml up -d

# Продукція
docker compose -f deploy/docker/docker-compose.yml -f deploy/docker/docker-compose.production.yml up -d
```

Або використовуйте скрипт налаштування:

```bash
./scripts/docker-setup.sh                                     # локально
./scripts/docker-setup.sh --domain hotline.org --email a@b   # продукція
```

## Основні служби

Усі цілі розгортання запускають ці основні служби:

| Компонент | Призначення |
|-----------|-------------|
| **Додаток Bun** | Сервер API Hono + обслуговування статичних файлів |
| **PostgreSQL** | Основна база даних |
| **RustFS** | S3-сумісне сховище blob (голосова пошта, вкладення, експорти) |
| **Релей WebSocket** | Релей WebSocket для подій у реальному часі (завжди обов'язковий) |
| **Caddy** | Зворотний проксі + автоматичний TLS (Docker Compose) |

## Додаткові служби

| Компонент | Профіль | Призначення |
|-----------|---------|-------------|
| **signal-notifier** | `signal` | Сайдкар сповіщень Signal з нульовим знанням (порт 3100) |
| **sip-bridge** | `telephony` | SIP міст для Asterisk/FreeSWITCH/Kamailio (PBX_TYPE вибирає бекенд) |
| **Ollama/vLLM** | `inference` | LLM інференс для вилучення повідомлень |
| **Prometheus + Grafana** | `monitoring` | Метрики та сповіщення |

## Що вам потрібно

### Мінімальні вимоги

- Сервер Linux (2 ядра CPU, 2 ГБ оперативної пам'яті мінімум)
- Docker та Docker Compose v2 (або кластер Kubernetes для Helm)
- Доменне ім'я, вказане на ваш сервер
- `openssl` (для генерації секретів)
- Принаймні один налаштований канал зв'язку

### Додаткові компоненти

- **Транскрипція** — клієнтська WASM Whisper; додатковий серверний компонент не потрібен
- **SIP міст** — для самостійно розміщеної АТС (Asterisk/FreeSWITCH/Kamailio)
- **Міст Signal** — для обміну повідомленнями Signal

## Cloudflare Tunnels (альтернативний вхід)

Замість відкриття портів 80/443 безпосередньо ви можете використовувати [Cloudflare Tunnels](https://www.cloudflare.com/products/tunnel/) для доступу. Це приховує IP вашого сервера та забезпечує захист від DDoS:

```bash
cloudflared tunnel create llamenos
cloudflared tunnel route dns llamenos hotline.yourorg.com
cloudflared tunnel run llamenos
```

Налаштуйте тунель для перенаправлення на `http://localhost:3000`.

## Міркування щодо безпеки

Самостійний хостинг дає більше контролю, але також більше відповідальності:

- **Дані у стані спокою**: Дані PostgreSQL зберігаються незашифрованими за замовчуванням. Використовуйте повно-дискове шифрування (LUKS, dm-crypt) на вашому сервері. Нотатки дзвінків, розшифровки та повідомлення захищені наскрізним шифруванням — сервер ніколи не бачить відкритий текст.
- **Мережева безпека**: Використовуйте брандмауер. Лише порти 80/443 мають бути загальнодоступними.
- **Секрети**: Ніколи не розміщуйте секрети у файлах Docker Compose або системах контролю версій. Використовуйте файли `.env` (в gitignore) або секрети Docker/Kubernetes.
- **Оновлення**: Регулярно отримуйте нові образи. Слідкуйте за журналом змін щодо виправлень безпеки.
- **Резервне копіювання**: Регулярно створюйте резервні копії бази даних PostgreSQL та сховища RustFS.

## Плейбуки Ansible

Каталог `deploy/ansible/` містить плейбуки попередньої перевірки та перевірки після розгортання:

```bash
# Перевірка системи перед розгортанням
ansible-playbook deploy/ansible/preflight.yml -i your_inventory

# Перевірка після розгортання
ansible-playbook deploy/ansible/smoke-check.yml -i your_inventory
```
