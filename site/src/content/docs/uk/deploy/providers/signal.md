Llamenos підтримує обмін повідомленнями Signal через самостійно розгорнутий [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api). Signal пропонує найсильніші гарантії конфіденційності з усіх каналів обміну повідомленнями, що робить його ідеальним для чутливих сценаріїв реагування на кризи.

## Передумови

- Сервер або віртуальна машина Linux для мосту (може бути тим самим сервером, що й Asterisk, або окремим)
- Docker встановлено на сервері мосту
- Виділений телефонний номер для реєстрації Signal
- Мережевий доступ від мосту до вашого сервера Llamenos

## Архітектура

![Signal Bridge Architecture](/diagrams/signal-bridge.svg)

Міст signal-cli працює на вашій інфраструктурі та пересилає повідомлення на ваш сервер через HTTP-вебхуки. Це означає, що ви контролюєте весь шлях повідомлення від Signal до вашої програми.

## 1. Розгорніть міст signal-cli

Запустіть контейнер Docker signal-cli-rest-api:

```bash
docker run -d \
  --name signal-cli \
  --restart unless-stopped \
  -p 8080:8080 \
  -v signal-cli-data:/home/.local/share/signal-cli \
  -e MODE=json-rpc \
  bbernhard/signal-cli-rest-api:latest
```

## 2. Зареєструйте телефонний номер

Зареєструйте міст із виділеним телефонним номером:

```bash
# Запит коду підтвердження через SMS
curl -X POST http://localhost:8080/v1/register/+1234567890

# Підтвердьте за допомогою отриманого коду
curl -X POST http://localhost:8080/v1/register/+1234567890/verify/123456
```

## 3. Налаштуйте пересилання вебхуків

Налаштуйте міст для пересилання вхідних повідомлень на ваш сервер:

```bash
curl -X PUT http://localhost:8080/v1/about \
  -H "Content-Type: application/json" \
  -d '{
    "webhook": {
      "url": "https://your-domain.com/api/messaging/signal/webhook",
      "headers": {
        "Authorization": "Bearer your-webhook-secret"
      }
    }
  }'
```

## 4. Увімкніть Signal у налаштуваннях адміністратора

Перейдіть до **Admin Settings > Messaging Channels** (або скористайтеся майстром налаштування) та увімкніть перемикач **Signal**.

Введіть наступне:
- **Bridge URL** — URL-адреса вашого мосту signal-cli (наприклад, `https://signal-bridge.example.com:8080`)
- **Bridge API Key** — токен bearer для автентифікації запитів до мосту
- **Webhook Secret** — секрет, що використовується для перевірки вхідних вебхуків (повинен збігатися з налаштуванням на кроці 3)
- **Registered Number** — телефонний номер, зареєстрований у Signal

## 5. Перевірка

Надішліть повідомлення Signal на свій зареєстрований номер. Розмова повинна з'явитися у вкладці **Conversations**.

## Моніторинг працездатності

Llamenos відстежує стан мосту signal-cli:
- Періодичні перевірки стану на кінцеву точку `/v1/about` мосту
- Плавна деградація, якщо міст недоступний — інші канали продовжують працювати
- Сповіщення адміністратору, коли міст виходить з ладу

## Транскрипція голосових повідомлень

Голосові повідомлення Signal можна транскрибувати безпосередньо в браузері волонтера за допомогою клієнтського Whisper (WASM через `@huggingface/transformers`). Аудіо ніколи не залишає пристрій — транскрипт шифрується та зберігається поряд із голосовим повідомленням у вікні розмови. Волонтери можуть увімкнути або вимкнути транскрипцію в особистих налаштуваннях.

## Примітки щодо безпеки

- Signal забезпечує наскрізне шифрування між користувачем і мостом signal-cli
- Міст розшифровує повідомлення для пересилання їх як вебхуків — сервер мосту має доступ до відкритого тексту
- Автентифікація вебхуків використовує токени bearer з порівнянням за сталим часом
- Тримайте міст у тій самій мережі, що й ваш сервер Asterisk (якщо застосовно), для мінімального розкриття
- Міст зберігає історію повідомлень локально в тому Docker — розгляньте можливість шифрування зберігання
- Для максимальної конфіденційності: самостійно розгорніть як Asterisk (голос), так і signal-cli (обмін повідомленнями) на власній інфраструктурі

## Вирішення проблем

- **Міст не отримує повідомлення**: Перевірте, чи номер телефону правильно зареєстровано за допомогою `GET /v1/about`
- **Невдачі доставки вебхуків**: Переконайтеся, що URL-адреса вебхука доступна з сервера мосту та що заголовок авторизації збігається
- **Проблеми реєстрації**: Деякі телефонні номери можуть потребувати відв'язки від наявного облікового запису Signal спочатку
