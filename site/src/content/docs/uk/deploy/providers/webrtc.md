---
title: Виклики через браузер WebRTC
description: Увімкніть відповідь на виклики в браузері для волонтерів за допомогою WebRTC.
---

WebRTC (Web Real-Time Communication) дозволяє волонтерам відповідати на виклики гарячої лінії безпосередньо в браузері, без необхідності використовувати телефон. Це корисно для волонтерів, які не хочуть розкривати свій номер телефону або працюють із комп'ютера.

## Як це працює

1. Адміністратор увімкнув WebRTC в налаштуваннях телефонного провайдера
2. Волонтери встановлюють свою перевагу виклику "Browser" у своєму профілі
3. Коли надходить виклик, додаток Llamenos дзвонить у браузері зі сповіщенням
4. Волонтер натискає "Answer", і виклик підключається через браузер за допомогою мікрофона

Аудіо виклику маршрутизується від телефонного провайдера через WebRTC-з'єднання до браузера волонтера. Якість виклику залежить від інтернет-з'єднання волонтера.

## Передумови

### Налаштування адміністратора

- Підтримуваний телефонний провайдер з увімкненим WebRTC (Twilio, SignalWire, Vonage або Plivo)
- Налаштовані облікові дані WebRTC конкретного провайдера (див. посібники з налаштування провайдера)
- WebRTC увімкнено в **Settings** > **Telephony Provider**

### Вимоги до волонтера

- Сучасний браузер (Chrome, Firefox, Edge або Safari 14.1+)
- Працюючий мікрофон
- Стабільне інтернет-з'єднання (мінімум 100 кбіт/с у обидва боки)
- Надані дозволи на сповіщення браузера

## Налаштування для конкретного провайдера

Кожен телефонний провайдер потребує різних облікових даних для WebRTC:

### Twilio / SignalWire

1. Створіть **API Key** у консолі провайдера
2. Створіть **TwiML/LaML Application** з Voice URL, встановленим на `https://your-domain.com/api/telephony/webrtc-incoming`
3. У Llamenos введіть API Key SID, API Key Secret та Application SID

### Vonage

1. Ваш додаток Vonage вже включає можливість WebRTC
2. У Llamenos вставте **private key** вашого додатка (формат PEM)
3. Application ID уже налаштовано з початкового налаштування

### Plivo

1. Створіть **Endpoint** у консолі Plivo в розділі **Voice** > **Endpoints**
2. WebRTC використовує ваші наявні Auth ID та Auth Token
3. Увімкніть WebRTC у Llamenos — додаткові облікові дані не потрібні

### Asterisk

WebRTC від Asterisk потребує налаштування SIP.js із транспортом WebSocket. Це складніше, ніж у хмарних провайдерів:

1. Увімкніть транспорт WebSocket у `http.conf` Asterisk
2. Створіть кінцеві точки PJSIP для WebRTC-клієнтів із DTLS-SRTP
3. Llamenos автоматично налаштовує клієнт SIP.js, коли обрано Asterisk

Див. [посібник із налаштування Asterisk](/docs/deploy/providers/asterisk) для повних деталей.

## Налаштування переваги виклику для волонтера

Волонтери налаштовують свою перевагу виклику в додатку:

1. Увійдіть до Llamenos
2. Перейдіть до **Settings** (значок шестерні)
3. У розділі **Call Preferences** оберіть **Browser** замість **Phone**
4. Надайте дозволи на використання мікрофона та сповіщень, коли з'явиться запит
5. Тримайте вкладку Llamenos відкритою під час зміни

Коли надходить виклик, ви побачите сповіщення браузера та індикатор дзвінка в додатку. Натисніть **Answer**, щоб підключитися.

## Поради щодо якості аудіо

- Використовуйте гарнітуру або навушники, щоб запобігти луну
- Закрийте інші програми, які використовують мікрофон
- За можливості використовуйте дротове інтернет-з'єднання
- Вимкніть розширення браузера, які можуть заважати WebRTC (VPN-розширення, блокувальники реклами із захистом від витоку WebRTC)

## Вирішення проблем

### Немає аудіо

- **Перевірте дозволи мікрофона**: Натисніть значок замка в адресному рядку та переконайтеся, що доступ до мікрофона встановлено на "Allow"
- **Перевірте свій мікрофон**: Використовуйте вбудований тест аудіо вашого браузера або сайт на кшталт [webcamtest.com](https://webcamtest.com)
- **Перевірте вихід аудіо**: Переконайтеся, що ваші динаміки або гарнітура обрані як пристрій виведення

### Виклики не дзвонять у браузері

- **Сповіщення заблоковано**: Перевірте, чи ввімкнено сповіщення браузера для сайту Llamenos
- **Вкладка не активна**: Вкладка Llamenos має бути відкрита (вона може бути у фоні, але вкладка має існувати)
- **Перевага виклику**: Переконайтеся, що ваша перевага виклику встановлена на "Browser" у налаштуваннях
- **WebRTC не налаштовано**: Попросіть адміністратора перевірити, чи ввімкнено WebRTC та встановлені облікові дані

### Проблеми з брандмауером і NAT

WebRTC використовує сервери STUN/TURN для проходження брандмауерів і NAT. Якщо виклики підключаються, але ви не чуєте аудіо:

- **Корпоративні брандмауери**: Деякі брандмауери блокують UDP-трафік на нестандартних портах. Попросіть свою ІТ-команду дозволити UDP-трафік на портах 3478 і 10000–60000
- **Симетричний NAT**: Деякі маршрутизатори використовують симетричний NAT, який може перешкоджати прямим з'єднанням між одноранговими вузлами. TURN-сервери вашого телефонного провайдера повинні обробляти це автоматично
- **Втручання VPN**: VPN можуть заважати з'єднанням WebRTC. Спробуйте відключити VPN під час змін

### Луна або зворотний зв'язок

- Використовуйте навушники замість динаміків
- Зменшіть чутливість мікрофона в налаштуваннях аудіо ОС
- Увімкніть пригнічення луни у вашому браузері (зазвичай увімкнено за замовчуванням)
- Відійдіть від твердих відбиваючих поверхонь
