Llamenos သည် ကိုယ်တိုင်လက်ခံထားသော [signal-cli-rest-api](https://github.com/bbernhard/signal-cli-rest-api) တံတားမှတစ်ဆင့် Signal မက်ဆေ့ချ်ပို့ခြင်းကို ပံ့ပိုးထားသည်။ Signal သည် မည်သည့်မက်ဆေ့ချ်ချန်နယ်ထက်မဆို အားကောင်းသော ကိုယ်ရေးလုံခြုံမှုအာမခံချက်များကို ပေးဆောင်ပြီး အရေးပေါ်အကျပ်အတည်းတုံ့ပြန်ရေးအခြေအနေများအတွက် စံပြဖြစ်စေသည်။

## ကြိုတင်လိုအပ်ချက်များ

- တံတားအတွက် Linux ဆာဗာ သို့မဟုတ် VM (Asterisk နှင့်အတူတူဆာဗာဖြစ်နိုင်၊ သို့မဟုတ် သီးခြားဖြစ်နိုင်)
- တံတားဆာဗာတွင် Docker ထည့်သွင်းထားရန်
- Signal မှတ်ပုံတင်အတွက် သီးသန့်ဖုန်းနံပါတ်တစ်ခု
- တံတားမှ သင့် Llamenos ဆာဗာသို့ ကွန်ရက်ဝင်ရောက်ခွင့်

## ဗိသုကာ

![Signal တံတားဗိသုကာ](/diagrams/signal-bridge.svg)

signal-cli တံတားသည် သင့်အခြေခံအဆောက်အအုံပေါ်တွင် လည်ပတ်ပြီး မက်ဆေ့ချ်များကို HTTP webhooks မှတစ်ဆင့် သင့်ဆာဗာသို့ ထပ်ဆင့်ပို့သည်။ ဆိုလိုသည်မှာ Signal မှ သင့်အက်ပလီကေးရှင်းသို့ မက်ဆေ့ချ်လမ်းကြောင်းတစ်ခုလုံးကို သင်ထိန်းချုပ်နိုင်သည်။

## 1. signal-cli တံတားကို ဖြန့်ကျက်ပါ

signal-cli-rest-api Docker ကွန်တိန်နာကို လည်ပတ်ပါ:

```bash
docker run -d \
  --name signal-cli \
  --restart unless-stopped \
  -p 8080:8080 \
  -v signal-cli-data:/home/.local/share/signal-cli \
  -e MODE=json-rpc \
  bbernhard/signal-cli-rest-api:latest
```

## 2. ဖုန်းနံပါတ်တစ်ခုကို မှတ်ပုံတင်ပါ

သီးသန့်ဖုန်းနံပါတ်တစ်ခုဖြင့် တံတားကို မှတ်ပုံတင်ပါ:

```bash
# SMS မှတစ်ဆင့် အတည်ပြုကုဒ်ကို တောင်းဆိုပါ
curl -X POST http://localhost:8080/v1/register/+1234567890

# သင်ရရှိသောကုဒ်ဖြင့် အတည်ပြုပါ
curl -X POST http://localhost:8080/v1/register/+1234567890/verify/123456
```

## 3. Webhook ထပ်ဆင့်ပို့ခြင်းကို သတ်မှတ်ပါ

ဝင်လာသောမက်ဆေ့ချ်များကို သင့်ဆာဗာသို့ ထပ်ဆင့်ပို့ရန် တံတားကို သတ်မှတ်ပါ:

```bash
curl -X PUT http://localhost:8080/v1/about \
  -H "Content-Type: application/json" \
  -d '{
    "webhook": {
      "url": "https://your-domain.com/api/messaging/signal/webhook",
      "headers": {
        "Authorization": "Bearer your-webhook-secret"
      }
    }
  }'
```

## 4. အက်ဒ်မင်ဆက်တင်များတွင် Signal ကိုဖွင့်ပါ

**အက်ဒ်မင်ဆက်တင်များ > မက်ဆေ့ချ်ချန်နယ်များ** သို့ သွားပါ (သို့မဟုတ် setup wizard ကိုသုံးပါ) ပြီး **Signal** ကိုဖွင့်ပါ။

အောက်ပါတို့ကို ထည့်သွင်းပါ:
- **တံတား URL** — သင့် signal-cli တံတား၏ URL (ဥပမာ `https://signal-bridge.example.com:8080`)
- **တံတား API သော့** — တံတားသို့ တောင်းဆိုမှုများကို အထောက်အထားစစ်ဆေးရန် bearer တိုကင်
- **Webhook လျှို့ဝှက်ချက်** — ဝင်လာသော webhook များကို အတည်ပြုရန် အသုံးပြုသည့် လျှို့ဝှက်ချက် (အဆင့် 3 တွင် သင်သတ်မှတ်ထားသည့်အတိုင်း တူညီရမည်)
- **မှတ်ပုံတင်ထားသောနံပါတ်** — Signal တွင် မှတ်ပုံတင်ထားသော ဖုန်းနံပါတ်

## 5. စမ်းသပ်ပါ

သင့်မှတ်ပုံတင်ထားသော ဖုန်းနံပါတ်သို့ Signal မက်ဆေ့ချ်တစ်စောင် ပို့ပါ။ စကားပြောဆိုမှုသည် **စကားပြောဆိုမှုများ** တက်ဘ်တွင် ပေါ်လာသင့်ပါသည်။

## ကျန်းမာရေးစောင့်ကြည့်ခြင်း

Llamenos သည် signal-cli တံတား၏ ကျန်းမာရေးကို စောင့်ကြည့်သည်:
- တံတား၏ `/v1/about` အဆုံးမှတ်သို့ အချိန်အခါအလိုက် ကျန်းမာရေးစစ်ဆေးမှုများ
- တံတားကိုမရောက်ရှိနိုင်ပါက ညင်သာစွာ စွမ်းဆောင်ရည်ကျဆင်းခြင်း — အခြားချန်နယ်များ ဆက်လက်အလုပ်လုပ်သည်
- တံတားပျက်သွားသောအခါ အက်ဒ်မင်သတိပေးချက်များ

## အသံမက်ဆေ့ချ် စာသားပြောင်းခြင်း

Signal အသံမက်ဆေ့ချ်များကို client-side Whisper (WASM မှတစ်ဆင့် `@huggingface/transformers`) ကိုအသုံးပြု၍ စေတနာ့ဝန်ထမ်း၏ဘရောက်ဆာတွင် တိုက်ရိုက်စာသားပြောင်းနိုင်သည်။ အသံသည် စက်ပစ္စည်းမှ ဘယ်တော့မှ မထွက်ခွာပါ — စာသားပြောင်းထားသောအကြောင်းအရာကို ကုဒ်ဝှက်ပြီး အသံမက်ဆေ့ချ်နှင့်အတူ စကားပြောဆိုမှုမြင်ကွင်းတွင် သိမ်းဆည်းသည်။ စေတနာ့ဝန်ထမ်းများသည် ၎င်းတို့၏ ကိုယ်ပိုင်ဆက်တင်များတွင် စာသားပြောင်းခြင်းကို ဖွင့် သို့မဟုတ် ပိတ်နိုင်သည်။

## လုံခြုံရေးမှတ်စုများ

- Signal သည် အသုံးပြုသူနှင့် signal-cli တံတားကြားတွင် အဆုံးမှအဆုံး ကုဒ်ဝှက်ခြင်းကို ပေးဆောင်သည်
- တံတားသည် ၎င်းတို့ကို webhook များအဖြစ် ထပ်ဆင့်ပို့ရန် မက်ဆေ့ချ်များကို စာသားပြောင်းပေးသည် — တံတားဆာဗာတွင် ရိုးရိုးစာသားဝင်ရောက်ခွင့်ရှိသည်
- Webhook အထောက်အထားစစ်ဆေးခြင်းသည် အဆက်မပြတ်အချိန်နှိုင်းယှဉ်မှုဖြင့် bearer တိုကင်များကို အသုံးပြုသည်
- တံတားကို သင့် Asterisk ဆာဗာနှင့် တူညီသောကွန်ရက်ပေါ်တွင်ထားပါ (သက်ဆိုင်ပါက) ထိတွေ့မှုအနည်းဆုံးဖြစ်စေရန်
- တံတားသည် ၎င်း၏ Docker volume တွင် မက်ဆေ့ချ်မှတ်တမ်းကို ဒေသအလိုက်သိမ်းဆည်းသည် — အနားယူချိန်တွင် ကုဒ်ဝှက်ခြင်းကို စဉ်းစားပါ
- အမြင့်ဆုံးကိုယ်ရေးလုံခြုံမှုအတွက်: သင့်ကိုယ်ပိုင်အခြေခံအဆောက်အအုံပေါ်တွင် Asterisk (အသံ) နှင့် signal-cli (မက်ဆေ့ချ်ပို့ခြင်း) နှစ်ခုလုံးကို ကိုယ်တိုင်လက်ခံပါ

## ပြဿနာဖြေရှင်းခြင်း

- **တံတားမက်ဆေ့ချ်များမရရှိခြင်း**: ဖုန်းနံပါတ်ကို `GET /v1/about` ဖြင့် မှန်ကန်စွာမှတ်ပုံတင်ထားကြောင်း စစ်ဆေးပါ
- **Webhook ပို့ဆောင်မှုမအောင်မြင်ခြင်း**: webhook URL ကို တံတားဆာဗာမှရောက်ရှိနိုင်ပြီး ခွင့်ပြုချက်ခေါင်းစီးတူညီကြောင်း စစ်ဆေးပါ
- **မှတ်ပုံတင်မှုပြဿနာများ**: အချို့ဖုန်းနံပါတ်များကို လက်ရှိ Signal အကောင့်တစ်ခုမှ ဦးစွာဖြုတ်ထားရန် လိုအပ်နိုင်သည်
