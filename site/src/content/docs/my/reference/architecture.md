ဤစာမျက်နှာသည် Llámenos ၏ ဖွဲ့စည်းပုံ၊ စနစ်အတွင်း ဒေတာစီးဆင်းပုံနှင့် ကုဒ်ဝှက်ခြင်းကို မည်သည့်နေရာတွင် အသုံးပြုသည်ကို ရှင်းပြသည်။

## သိုလှောင်ရာဖွဲ့စည်းပုံ

Llámenos သည် ဘုံပရိုတိုကောနှင့် ကုဒ်ဝှက်ဆိုင်ရာ ဗဟိုချက်ကို မျှဝေသော သိုလှောင်ရာသုံးခုတွင် ခွဲထားသည်-

```
llamenos              llamenos-core           llamenos-platform
(Desktop + API)       (Shared Crypto)         (Mobile App)
+--------------+      +--------------+        +--------------+
| Tauri v2     |      | Rust crate   |        | React Native |
| Vite + React |      | - Native lib |        | iOS + Android|
| CF Workers   |      | - WASM pkg   |        | UniFFI bind  |
| Durable Objs |      | - UniFFI     |        |              |
+--------------+      +--------------+        +--------------+
       |                  ^      ^                   |
       |  path dep        |      |    UniFFI         |
       +------------------+      +-------------------+
```

- **llamenos** — ဒက်စ်တော့အက်ပလီကေးရှင်း (Tauri v2 နှင့် Vite + React webview ပါသော)၊ Cloudflare Worker backend နှင့် ကိုယ်တိုင်လက်ခံဆောင်ရွက်သော Node.js backend တို့ဖြစ်သည်။ ဤသည်မှာ အဓိကသိုလှောင်ရာဖြစ်သည်။
- **llamenos-core** — ကုဒ်ဝှက်ဆိုင်ရာ လုပ်ဆောင်ချက်အားလုံးကို အကောင်အထည်ဖော်သော မျှဝေသုံး Rust crate တစ်ခုဖြစ်သည်- ECIES စာအိတ်ကုဒ်ဝှက်ခြင်း၊ Schnorr လက်မှတ်များ၊ PBKDF2 သော့ဆင်းသက်ခြင်း၊ HKDF နှင့် XChaCha20-Poly1305 တို့ဖြစ်သည်။ ဇာတိကုဒ် (Tauri အတွက်)၊ WASM (ဝဘ်ဘရောက်ဆာအတွက်) နှင့် UniFFI ချိတ်ဆက်မှုများ (မိုဘိုင်းအတွက်) အဖြစ် စုစည်းထားသည်။
- **llamenos-platform** — iOS နှင့် Android အတွက် React Native မိုဘိုင်းအက်ပလီကေးရှင်းဖြစ်သည်။ တူညီသော Rust ကုဒ်ဝှက်ကုဒ်သို့ ခေါ်ဆိုရန် UniFFI ချိတ်ဆက်မှုများကို အသုံးပြုသည်။

ပလက်ဖောင်းသုံးခုစလုံးသည် `docs/protocol/PROTOCOL.md` တွင် သတ်မှတ်ထားသော တူညီသည့် ဝိုင်ယာပရိုတိုကောကို အကောင်အထည်ဖော်သည်။

## Durable Objects

backend သည် Cloudflare Durable Objects ခြောက်ခု (သို့မဟုတ် ၎င်းတို့၏ PostgreSQL နှင့်ညီမျှသော ကိုယ်တိုင်လက်ခံဆောင်ရွက်သည့် ဖြန့်ကျက်မှုများအတွက်) ကို အသုံးပြုသည်-

| Durable Object | တာဝန်ခံမှု |
|---|---|
| **IdentityDO** | စေတနာ့ဝန်ထမ်းအထောက်အထားများ၊ အများသုံးသော့များ၊ ဖော်ပြမည့်အမည်များနှင့် WebAuthn အထောက်အထားများကို စီမံသည်။ ဖိတ်ကြားချက်ဖန်တီးခြင်းနှင့် အကောင်အထည်ဖော်ခြင်းကို ကိုင်တွယ်သည်။ |
| **SettingsDO** | အရေးပေါ်လိုင်းဖွဲ့စည်းမှု- အမည်၊ ဖွင့်ထားသော ချန်နယ်များ၊ ဝန်ဆောင်မှုပေးသူအထောက်အထားများ၊ စိတ်ကြိုက်မှတ်စုအကွက်များ၊ စပမ်းလျှော့ချရေးဆက်တင်များ၊ အင်္ဂါရပ်အလံများကို သိမ်းဆည်းသည်။ |
| **RecordsDO** | ကုဒ်ဝှက်ထားသော ခေါ်ဆိုမှုမှတ်စုများ၊ ကုဒ်ဝှက်ထားသော အစီရင်ခံစာများနှင့် ဖိုင်ပူးတွဲမှုမက်တာဒေတာများကို သိမ်းဆည်းသည်။ မှတ်စုရှာဖွေခြင်း (ကုဒ်ဝှက်ထားသော မက်တာဒေတာအပေါ်) ကို ကိုင်တွယ်သည်။ |
| **ShiftManagerDO** | ထပ်တလဲလဲအလုပ်ချိန်ဇယားများ၊ ခေါ်ဆိုမှုအဖွဲ့များ၊ စေတနာ့ဝန်ထမ်းအလုပ်ချိန်တာဝန်များကို စီမံသည်။ မည်သူသည် မည်သည့်အချိန်တွင် တာဝန်ကျသည်ကို ဆုံးဖြတ်သည်။ |
| **CallRouterDO** | အချိန်နှင့်တပြေးညီ ခေါ်ဆိုမှုလမ်းကြောင်းသတ်မှတ်ခြင်းကို စီစဉ်ပေးသည်- အပြိုင်ခေါ်ဆိုခြင်း၊ ပထမဆုံးဖြေကြားမှုရပ်ဆိုင်းခြင်း၊ အနားယူချိန်အနေအထား၊ လှုပ်ရှားနေသောခေါ်ဆိုမှုခြေရာခံခြင်း။ TwiML/ဝန်ဆောင်မှုပေးသူတုံ့ပြန်မှုများကို ထုတ်လုပ်သည်။ |
| **ConversationDO** | SMS၊ WhatsApp နှင့် Signal တို့တစ်လျှောက် ကြိုးဆက်စာတိုမက်ဆေ့ချ် ဆွေးနွေးမှုများကို စီမံသည်။ မက်ဆေ့ချ်ကုဒ်ဝှက်ခြင်းကို လက်ခံရရှိချိန်တွင်၊ ဆွေးနွေးမှုတာဝန်ပေးခြင်းနှင့် အကြောင်းပြန်စာများကို ကိုင်တွယ်သည်။ |

DO အားလုံးကို `idFromName()` မှတစ်ဆင့် singleton များအဖြစ် ဝင်ရောက်ကြည့်ရှုပြီး ပေါ့ပါးသော `DORouter` (နည်းလမ်း + လမ်းကြောင်းပုံစံကိုက်ညီခြင်း) ကို အသုံးပြု၍ အတွင်းပိုင်း လမ်းကြောင်းသတ်မှတ်သည်။

| စေတနာ့ဝန်ထမ်း nsec | ဟုတ်သည် (အနားယူချိန်တွင်) | PBKDF2 + XChaCha20-Poly1305 (PIN) | စေတနာ့ဝန်ထမ်းသာ |
| စာရင်းစစ်မှတ်တမ်းများ | မဟုတ်ပါ (ခိုင်မာမှုကာကွယ်ထား) | SHA-256 hash ကွင်းဆက် | အက်ဒမင်များ (ဖတ်ရန်)၊ စနစ် (ရေးရန်) |
| ခေါ်ဆိုသူဖုန်းနံပါတ်များ | မဟုတ်ပါ (ဆာဗာဘက်ခြမ်းသာ) | N/A | ဆာဗာ + အက်ဒမင်များ |
| စေတနာ့ဝန်ထမ်းဖုန်းနံပါတ်များ | IdentityDO တွင် သိမ်းဆည်းထား | N/A | အက်ဒမင်များသာ |

### မှတ်စုတစ်ခုချင်း ရှေ့သွားလျှို့ဝှက်မှု

မှတ်စု သို့မဟုတ် မက်ဆေ့ချ်တစ်ခုစီသည် ထူးခြားသော ကျပန်း symmetric သော့တစ်ခုရရှိသည်။ ထိုသော့ကို ခွင့်ပြုထားသော စာဖတ်သူတစ်ဦးချင်းစီအတွက် ECIES (secp256k1 ခဏတာသော့ + HKDF + XChaCha20-Poly1305) ဖြင့် တစ်ဦးချင်းထုပ်ပိုးထားသည်။ မှတ်စုတစ်ခု၏သော့ကို အလျှော့ပေးလိုက်ခြင်းသည် အခြားမှတ်စုများအကြောင်း မည်သည့်အရာကိုမျှ ဖော်ပြမည်မဟုတ်ပါ။ အကြောင်းအရာကုဒ်ဝှက်ခြင်းအတွက် ကြာရှည်ခံသော symmetric သော့များ မရှိပါ။

### သော့အထက်အောက်ဖွဲ့စည်းပုံ

```
စေတနာ့ဝန်ထမ်း nsec (BIP-340 Schnorr / secp256k1)
    |
    +-- npub (x-သာ အများသုံးသော့, 32 bytes) ကို ဆင်းသက်စေသည်
    |
    +-- ECIES သော့သဘောတူညီမှုအတွက် အသုံးပြုသည် (ချုံ့ထားသောပုံစံအတွက် 02 ထည့်ပါ)
    |
    +-- WebSocket ဖြစ်ရပ်များကို လက်မှတ်ရေးထိုးသည် (Schnorr လက်မှတ်)

Hub သော့ (ကျပန်း 32 bytes၊ မည်သည့်အထောက်အထားမှမဆင်းသက်ပါ)
    |
    +-- အချိန်နှင့်တပြေးညီ WebSocket hub ဖြစ်ရပ်များကို ကုဒ်ဝှက်သည်
    |
    +-- LABEL_HUB_KEY_WRAP မှတစ်ဆင့် အဖွဲ့ဝင်တစ်ဦးချင်းစီအတွက် ECIES ထုပ်ပိုးထား
    |
    +-- အဖွဲ့ဝင်ထွက်ခွာချိန်တွင် လှည့်ပြောင်းသည်

မှတ်စုတစ်ခုချင်းသော့ (ကျပန်း 32 bytes)
    |
    +-- XChaCha20-Poly1305 မှတစ်ဆင့် မှတ်စုပါအကြောင်းအရာကို ကုဒ်ဝှက်သည်
    |
    +-- စာဖတ်သူတစ်ဦးချင်းစီအတွက် ECIES ထုပ်ပိုးထား (စေတနာ့ဝန်ထမ်း + အက်ဒမင်တစ်ဦးချင်းစီ)
    |
    +-- မှတ်စုများတစ်လျှောက် ပြန်လည်အသုံးမပြုပါ
```

## အချိန်နှင့်တပြေးညီ ဆက်သွယ်မှု

အချိန်နှင့်တပြေးညီ အပ်ဒိတ်များ (ခေါ်ဆိုမှုအသစ်များ၊ မက်ဆေ့ချ်များ၊ အလုပ်ချိန်ပြောင်းလဲမှုများ၊ တည်ရှိမှု) သည် WebSocket relay တစ်ခုမှတစ်ဆင့် စီးဆင်းသည်-

- **ကိုယ်တိုင်လက်ခံဆောင်ရွက်ထား**: Docker/Kubernetes ရှိ အက်ပ်ဘေးတွင် လုပ်ဆောင်နေသော WebSocket relay
- **Cloudflare**: Nosflare (Cloudflare Workers-based relay)

ဖြစ်ရပ်အားလုံးသည် ခဏတာ (kind 20001) ဖြစ်ပြီး hub သော့ဖြင့် ကုဒ်ဝှက်ထားသည်။ ဖြစ်ရပ်များသည် ယေဘုယျ tag များ (`["t", "llamenos:event"]`) ကို အသုံးပြုသောကြောင့် relay သည် ဖြစ်ရပ်အမျိုးအစားများကို ခွဲခြားနိုင်မည်မဟုတ်ပါ။ content အကွက်တွင် XChaCha20-Poly1305 ciphertext ပါရှိသည်။

### ဖြစ်ရပ်စီးဆင်းမှု

```
Client A (စေတနာ့ဝန်ထမ်း လုပ်ဆောင်ချက်)
    |
    | hub သော့ဖြင့် ဖြစ်ရပ်ပါအကြောင်းအရာကို ကုဒ်ဝှက်သည်
    | WebSocket ဖြစ်ရပ်အဖြစ် လက်မှတ်ရေးထိုးသည် (Schnorr)
    v
WebSocket relay
    |
    | စာရင်းသွင်းထားသူများသို့ ထုတ်လွှင့်သည်
    v
Client B, C, D...
    |
    | Schnorr လက်မှတ်ကို အတည်ပြုသည်
    | hub သော့ဖြင့် အကြောင်းအရာကို ကုဒ်ဖော်သည်
    v
ဒေသခံ UI အခြေအနေကို အပ်ဒိတ်လုပ်သည်
```

Relay သည် ကုဒ်ဝှက်ထားသော blobs များနှင့် တရားဝင်သော လက်မှတ်များကို မြင်သော်လည်း ဖြစ်ရပ်ပါအကြောင်းအရာကို ဖတ်၍မရသည့်အပြင် မည်သည့်လုပ်ဆောင်ချက်များကို လုပ်ဆောင်နေသည်ကိုလည်း ဆုံးဖြတ်၍မရပါ။

## လုံခြုံရေးအလွှာများ

### ပို့ဆောင်ရေးအလွှာ

- HTTPS (TLS 1.3) မှတစ်ဆင့် client-server ဆက်သွယ်မှုအားလုံး
- WSS မှတစ်ဆင့် WebSocket relay သို့ WebSocket ချိတ်ဆက်မှုများ
- Content Security Policy (CSP) သည် script အရင်းအမြစ်များ၊ ချိတ်ဆက်မှုများနှင့် frame ဘိုးဘေးများကို ကန့်သတ်သည်
- Tauri isolation pattern သည် IPC ကို webview မှ ခွဲထုတ်သည်

### အပလီကေးရှင်းအလွှာ

- WebSocket သော့တွဲများ (BIP-340 Schnorr လက်မှတ်များ) မှတစ်ဆင့် စစ်မှန်ကြောင်းအထောက်အထားပြခြင်း
- စက်ပစ္စည်းအများအသုံးပြုနိုင်ရန် WebAuthn session token များ
- အခန်းကဏ္ဍအခြေပြု ဝင်ရောက်ခွင့်ထိန်းချုပ်ခြင်း (ခေါ်ဆိုသူ၊ စေတနာ့ဝန်ထမ်း၊ အစီရင်ခံသူ၊ အက်ဒမင်)
- `crypto-labels.ts` တွင် သတ်မှတ်ထားသော ကုဒ်ဝှက်ဆိုင်ရာ ဒိုမိန်းခွဲခြားသည့် ကိန်းသေ ၂၅ ခုစလုံးသည် ပရိုတိုကောဖြတ်ကျော်တိုက်ခိုက်မှုများကို တားဆီးသည်

### အနားယူချိန်ကုဒ်ဝှက်ခြင်း

- သိမ်းဆည်းခြင်းမပြုမီ ခေါ်ဆိုမှုမှတ်စုများ၊ အစီရင်ခံစာများ၊ မက်ဆေ့ချ်များနှင့် စကားဝိုင်းမှတ်တမ်းများကို ကုဒ်ဝှက်ထား
- စေတနာ့ဝန်ထမ်းလျှို့ဝှက်သော့များကို PIN မှဆင်းသက်သောသော့များ (PBKDF2) ဖြင့် ကုဒ်ဝှက်ထား
- Tauri Stronghold သည် ဒက်စ်တော့တွင် ကုဒ်ဝှက်ထားသော လုံခြုံသိုလှောင်မှုကို ပေးသည်
- SHA-256 hash ကွင်းဆက်မှတစ်ဆင့် စာရင်းစစ်မှတ်တမ်းခိုင်မာမှုကို ကာကွယ်ထား

### တည်ဆောက်မှုအတည်ပြုချက်

- `Dockerfile.build` နှင့် `SOURCE_DATE_EPOCH` ဖြင့် ပြန်လည်ထုတ်လုပ်နိုင်သော တည်ဆောက်မှုများ
- frontend assets များအတွက် အကြောင်းအရာ-hashed ဖိုင်အမည်များ
- GitHub Releases နှင့်အတူ `CHECKSUMS.txt` ကိုထုတ်ဝေသည်
- SLSA သက်သေခံလက်မှတ်များ
- အတည်ပြုစစ်ဆေးသည့် script: `scripts/verify-build.sh`
