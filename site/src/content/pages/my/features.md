## လုံခြုံရေး အနုပညာတည်ဆောက်ပုံ

Llámenos သည် ဖုန်းခေါ်ဆိုသူများနှင့် စေတနာ့ဝန်ထမ်းများကို ငွေကြေးပြည့်စုံသော ရန်သူများမှ အစဉ်အဆက်ကာကွယ်ရန် စတင်တည်ဆောက်ထားသည် — နိုင်ငံတကာ၊ လက်ယာရွေး အဖွဲ့များ၊ နှင့် ပုဂ္ဂလိက အသိပညာ ကုမ္ပဏီများ။ ဝှက်စာဆိုင်ရာ ဆုံးဖြတ်ချက်တိုင်းသည် ရည်ရွယ်ချက်ရှိသော၊ စာရွက်စာတမ်းပြုထားသော၊ နှင့် စစ်ဆေးနိုင်သော ဖြစ်သည်။

**HPKE (RFC 9180) — X25519-HKDF-SHA256-AES256-GCM** — MLS (Messaging Layer Security) နှင့် TLS 1.3 တွင် အသုံးပြုသော ဟိုက်ဘရစ် ဝှက်စာစံတူ ဖြစ်သည်။ အဟောင်း ECIES (secp256k1) ကို အစားထိုးလိုက်ပြီ။ RFC 9180 သည် ရုံးသားအတည်ပြုထားသော၊ အထက်လွှတ်တင်စစ်ဆေးထားသော တည်ဆောက်မှုကို ပေးသည်။

**မှတ်စုတိုင်းအတွက် forward secrecy** — မှတ်စုတိုင်းသည် ထူးခြားသော ကျပန်းသော့ကို သုံးပြီး၊ ထိုသော့ကို HPKE ဖြင့် တာဝန်ခံဖတ်ရှုသူတိုင်း (စေတနာ့ဝန်ထမ်းနှင့် အက်ဒမင် တိုင်း) အတွက် သီးခြားထုပ်ပိုးသည်။ ဖတ်ရှုသူ၏ ပုဂ္ဂလိကသော့ကို ချိုးဖောက်ပါက ချိုးဖောက်မီးမှ အရင်ကရေးထားသော မှတ်စုများအကြောင်း ဘာမျှမသိရှိနိုင်။ သော့အဆင့်များ: Per-User Key (PUK) → items_key → မှတ်စုတိုင်းအတွက် content key၊ cascading lazy rotation ဖြင့်။

**နှစ်ထပ်ဝှက်စာထားသော မှတ်စုများ** — မှတ်စုတိုင်းကို နှစ်ကြိမ်ဝှက်စာထားသည် — တစ်ကြိမ်မှာ စေတနာ့ဝန်ထမ်းအတွက် HPKE ဖြင့်၊ တစ်ကြိမ်မှာ အက်ဒမင် တိုင်းအတွက်။ နှစ်ဦးစလုံး ကိုယ်တိုင်ဖွင့်နိုင်သည်။ အခြားသူ — ဆာဗာပါဝင် — ဘယ်သူမှ စာသားကို မဖတ်နိုင်ပါ။

**ဒိုမိန်ခွဲခြားမှု လေဘယ်လ် ၅၇ ခု** — ဝှက်စာဆိုင်ရာ လုပ်ဆောင်ချက်တိုင်းသည် ထူးခြားသော ကွန်တက်စ် စာကြောင်း (Albrecht ကာကွယ်ရေး) ကို သုံးသည်။ လုပ်ဆောင်ချက် နှစ်ခုလုံး သော့ထုတ်လမ်းညွှန်ကို မျှဝေခြင်းမရှိပဲ၊ ပရိုတိုကော် ဖြတ်ကျော်တိုက်ခိုက်မှုများကို တားဆီးသည်။ လေဘယ်လ်များကို `packages/protocol/crypto-labels.json` တွင် သတ်မှတ်ထားပြီး TypeScript၊ Swift၊ နှင့် Kotlin အတွက် codegen ဖြင့် ထုတ်လုပ်သည်။ ဝှက်စာ ကွန်တက်တွင် ကျပန်းစာကြောင်း လစ်တာရများ ဘယ်တော့မှ မသုံးပါ။

**ကိရိယာတိုင်းအတွက် Ed25519/X25519 သော့များ** — အသုံးပြုသူများတွင် ကိရိယာတိုင်းအတွက် သော့များ (တစ်ခုတည်းသော အထောက်အထား သော့မဟုတ်) ရှိသည်။ ကိရိယာအသစ်များကို append-only၊ hash-chained၊ Ed25519-signed sigchain ဖြင့် တာဝန်ပေးသည်။ ကိရိယာ ချိတ်ဆက်မှုသည် ယာယီ ECDH provisioning room များကို သုံးပြီး၊ မိနစ် ၅ အတွင်း သက်တမ်းကုန်သည်။

**PIN-ဝှက်စာထားသော သော့သိမ်းဆည်းခြင်း** — ကိရိယာ ပုဂ္ဂလိကသော့များကို PBKDF2 ၆၀၀,၀၀၀ ကြိမ် + XChaCha20-Poly1305 ဖြင့် ဝှက်စာထားသည်။ သော့ကို အမှတ်ရာမှclosure တွင် သိမ်းပြီး၊ လော့ခ်ဖြစ်သောအခါ သုညပြုလုပ်သည်။ sessionStorage၊ IndexedDB၊ သို့မဟုတ် ဒစ်စ်တွင် စာသားပုံစံ ဘယ်တော့မှ မထိတွေ့ပါ။

**ပလက်ဖောင်း-မူလ လုံခြုံသော သိမ်းဆည်းခြင်း** — ဒက်စတော့: Tauri Stronghold ဝှက်စာထားသော vault။ iOS: iOS Keychain။ Android: Android Keystore မှတဆင့် EncryptedSharedPreferences။

**ကလိုင်ယံ-ဘက်သာ transcription** — ဖုန်းခေါ်ဆိုမှု transcription သည် WASM Whisper (`@huggingface/transformers` ONNX runtime) ကို ဘရောက်ဆာတွင် လုံးဝလည်ပတ်သည်။ အသံကို AudioWorklet ring buffer → Web Worker ပိုင်းစဉ်မှတဆင့် ဒေသန္တရဖြစ်စေသည်။ အသံသည် ဆာဗာသို့ ဘယ်တော့မှ မရောက် — ဝှက်စာထားသော ပုံစံဖြင့်ပင် မဟုတ်ပါ။

**SFrame အသံ E2EE** — SFrame (RFC 9605) ဖြင့် ဝှက်စာထားသော မီဒီယာ ရေဒီယိုများ၊ သော့ထုတ်လုပ်မှု မျှဝေထားသော Rust crypto crate နှင့် ပေါင်းစပ်ထား။

**မျှဝေထားသော Rust crypto crate** — `packages/crypto/` တွင် တစ်ခုတည်းသော စစ်ဆေးနိုင်သော အကောင်အထည်: native (Tauri desktop)、WASM (ဘရောက်ဆာ `@tauri-apps/api` မှ)、နှင့် UniFFI (iOS XCFramework + Android JNI) အတွက်။ သုံးခု ခွဲထားသော အကောင်အထည်များ မဟုတ်။

**Hash-chained စစ်တမ်းမှတ်တမ်း** — ဖုန်းခေါ်ဆိုမှုတိုင်း၊ မှတ်စုတိုင်း၊ မက်ဆေ့ချ်တိုင်း၊ အပြင်အဆင်ပြောင်းတိုင်း၊ နှင့် အက်ဒမင် လုပ်ဆောင်ချက်တိုင်း SHA-256 ချိန်ဆက်ခြင်း (`previousEntryHash` + `entryHash`) ဖြင့် မှတ်ပြီး၊ ပြုပြင်ထားခြင်း ရှာဖွေနိုင်သည်။ အက်ဒမင်များသည် ချိန်ဆက်မှု ညီညွတ်မှုကို စစ်ဆေးနိုင်သည်။

**ပြန်လည်ထုတ်လုပ်နိုင်သော တည်ဆောက်မှုများ** — `Dockerfile.build` နှင့် `SOURCE_DATE_EPOCH`၊ အကြောင်းအရာ-ဟက်ချ်ဖိုင်နာမည်။ SLSA provenance၊ SBOM၊ နှင့် cosign လက်မှတ် ထိုးခြင်း တိုင်းရင်းတိုင်းတွင်။ `scripts/verify-build.sh` ဖြင့် GitHub Releases ရှိ `CHECKSUMS.txt` နှင့် ဘိုက်-ဘိုက် စစ်ဆေးနိုင်သည်။

## တယ်လီဖုန်း — ပေးသွင်းသူ ၈ ခု

**အများစု ပလက်ဖောင်းများက တစ်ခုတည်းသော ပေးသွင်းသူသာ ခိုင်းစေသည်ထက် ကွဲပြားစွာ**၊ Llámenos သည် `TelephonyAdapter` အင်တာဖေ့စ် ဖြင့် အပြည့်အစုံ အကောင်အထည် ၈ ခုကို အကောင်အထည်ဖော်ထားသည်။ အက်ဒမင် UI မှတဆင့် ပေးသွင်းသူပြောင်းလဲပါ — ကုဒ်ပြောင်းစရာမလို၊ ဆာဗာရပ်စရာမလို။

### ကလော့ဒ် ပေးသွင်းသူများ (၆)

- **Twilio** — အပြည့်အစုံ WebRTC၊ ပရိုဂရမ်ပြုလုပ်နိုင်သော အသံ၊ SIP trunking
- **SignalWire** — Twilio နှင့်ကိုက်ညီသော API၊ အသုံးစရိတ်နည်း၊ WebRTC ပံ့ပိုးမှု
- **Vonage** (Nexmo) — ဥရောပ ဒေတာ နေရာထိုင်ခင်းရွေးချယ်ခွင့်
- **Plivo** — ကုန်ကျစရိတ်သင့်၊ ကမ္ဘာလုံးဆိုင်ရာ ဖုံးအုပ်
- **Telnyx** — အပြိုင်အဆိုင်စျေး၊ Mission Control Portal ပေါင်းစပ်မှု
- **Bandwidth** — အဆင့်မြင့်၊ အမေရိကန် ကယ်ရီယာ-အဆင့်မီ ယုံကြည်မှု

### ကိုယ်ပိုင် ဟော့စ် SIP (၂)

- **Asterisk** — ARI (Asterisk REST Interface) မှတဆင့်။ အပြည့်အစုံ ခေါ်ဆိုမှု ထိန်းချုပ်မှု၊ IVR၊ မှတ်တမ်း။
- **FreeSWITCH** — ESL (Event Socket Library) မှတဆင့်။ အထွတ်အထိပ်၊ အစည်းအဝေး-စွမ်းရည်။

နှစ်ခုစလုံး `SipBridgeAdapter` အခြေခံအတန်း နှင့် `PBX_TYPE` env var ကို သုံးပြီး backend ရွေးချယ်သည်။ Kamailio သည် SIP proxy အဆင့်အဖြစ် ပံ့ပိုးထားသည်။ **ဖုန်းခေါ်ဆိုမှု မှတ်တမ်းများ သင့်ဆာဗာမှ ဘယ်တော့မှ မထွက်ပါ။**

### ခေါ်ဆိုမှု လမ်းညွှန်

**တပြိုင်နက်တည်း ဖုန်းမြည်ခြင်း** — ဖုန်းခေါ်ဆိုသူ ဝင်ခေါ်သောအခါ၊ လှည့်ကိုင် နေသော၊ မအားသော စေတနာ့ဝန်ထမ်း အားလုံး တပြိုင်နက်တည်း ဖုန်းမြည်သည်။ ပထမဆုံး သုံးသူ အနိုင်ရသည်။ အခြားသူများ ချက်ချင်း ရပ်သွားသည်။ အစဉ်လိုက် လိုက်ရှာခြင်းကြောင့် ဖုန်းလွတ်တာ မရှိပါ။

**လှည့်ကိုင် အခြေခံ အချိန်ဇယား** — နေ့ရက် နှင့် အချိန်အပိုင်းအခြား သတ်မှတ်ထားသော ထပ်ခါထပ်ခါ လှည့်ကိုင်ချိန်များ ဖန်တီးပြီး၊ စေတနာ့ဝန်ထမ်းများကို ခန့်ထားနိုင်သည်။ စနစ်သည် အလုပ်လုပ်နေသူများသို့ အလိုအလျောက် ဖုန်းလွှဲသည်။ အချိန်ဇယား မသတ်မှတ်ထားပါက fallback ring group သို့ လွှဲသည်။

**စောင့်ဆိုင်းမှု ဂီတဖြင့် စီတင်မှု** — စေတနာ့ဝန်ထမ်းအားလုံး အလုပ်များနေပါက၊ ဖုန်းခေါ်ဆိုသူများ စီတင်စာရင်းသို့ ဝင်ပြီး၊ ပြုပြင်ထားသော စောင့်ဆိုင်းဂီတကို နားထောင်နိုင်သည်။ အချိန်ကုန်ချိန် ပြုပြင်နိုင်သည် (၃၀–၃၀၀ စက္ကန့်)။ မဖြေဆိုပါက voicemail သို့ ရောက်သည်။

**Voicemail fallback** — ဖုန်းခေါ်ဆိုသူများ voicemail ထားနိုင်သည် (မိနစ် ၅ အထိ)။ Voicemail များကို ကလိုင်ယံ-ဘက် Whisper ဖြင့် transcription လုပ်ပြီး၊ အက်ဒမင် စစ်ဆေးရန် ဝှက်စာထားသည်။

**WebRTC ဘရောက်ဆာ ခေါ်ဆိုမှု** — စေတနာ့ဝန်ထမ်းများသည် ဖုန်းမလိုဘဲ ဘရောက်ဆာတွင် တိုက်ရိုက် ဖုန်းဖြေနိုင်သည်။ Twilio၊ SignalWire၊ Vonage၊ နှင့် Plivo အတွက် provider-သီးခြား WebRTC token ထုတ်လုပ်မှု။

**Spam တားဆီးမှု** — အသံ CAPTCHA (ကျပန်း ၄-လုံး ကီးပဒ် ထည့်သွင်းမှု)、တယ်လီဖုန်းနံပါတ် တစ်ခုချင်းစီ အပေါ် စလိုက်ဝင်းဒိုး rate limiting၊ နှင့် တိုက်ရိုက်ချိန် ban စာရင်း။ အက်ဒမင်များသည် ထိန်းချုပ်မှုတိုင်းကို သီးခြားစီ ဖွင့်နိုင်/ပိတ်နိုင်၊ ပြန်လည်စတင်စရာမလို။ TTS fallback ဖြင့် ပြုပြင်ထားသော IVR prompts။

## မက်ဆေ့ချ်ပို့ရေး — ရေဒီယို ၅ ခု

ရေဒီယိုအားလုံး ဝှက်စာထားသော စကားပြောဆိုမှု မော်ဒယ်တစ်ခုကို မျှဝေသည်။ ဝင်ရောက်လာသော မက်ဆေ့ချ်တိုင်းကို webhook လက်ခံသောအခါ HPKE ဖြင့် ဝှက်စာထားသည်။ ဆာဗာသည် စာသားပုံစံ ချက်ချင်း ဖျက်စီးသည်။

### Signal

ရရှိနိုင်သော အပြည့်အစုံဆုံး non-Twilio ပေါင်းစပ်မှု။ Signal adapter တွင် အောက်ပါအရာများ ပါဝင်သည်:

- ပို့မှု/လက်ခံမှု အပြည့်အစုံ နှင့် delivery receipts
- ဖတ်ရှုမှု receipts နှင့် typing indicators
- Reactions နှင့် reply threading
- signal-cli-rest-api bridge မှတဆင့် မှတ်ပုံတင်ခြင်း နှင့် ချိတ်ဆက်ခြင်း
- အထောက်အထား ယုံကြည်မှု စစ်ဆေးခြင်း နှင့် လုံခြုံနံပါတ် စီမံခန့်ခွဲမှု
- ထပ်ကြိုးစားမှု စီတင် နှင့် exponential backoff
- Bridge ပျက်ကွက်သောအခါ အခြား သယ်ယူပို့ဆောင်ရေး failover
- ကလိုင်ယံ-ဘက် Whisper ဖြင့် အသံမက်ဆေ့ချ် transcription
- ကျန်းမာရေး စောင့်ကြည့်မှု နှင့် ကျင့်သားဆန်သော အဆင့်ကျမှု

### WhatsApp Business

- Meta Cloud API (Graph API v21.0)
- Template မက်ဆေ့ချ် ပံ့ပိုးမှု ၂၄-နာရီ window ကိုက်ညီမှုအတွက်
- မီဒီယာ မက်ဆေ့ချ်များ: ပုံများ၊ စာရွက်စာတမ်း၊ အသံ၊ ဗီဒီယို
- Webhook လက်မှတ် စစ်ဆေးခြင်း
- ဖတ်ရှုမှု receipts နှင့် ပို့ဆောင်မှု အခြေအနေ

### SMS

- Twilio၊ SignalWire၊ Vonage၊ သို့မဟုတ် Plivo မှတဆင့် ဝင်ရောက်/ထွက်ခွာ
- ဘာသာစကားတိုင်းအတွက် ပြုပြင်နိုင်သော ကြိုဆိုမက်ဆေ့ချ်ဖြင့် အလိုအလျောက် တုံ့ပြန်မှု
- ရရှိနိုင်သည့်နေရာတွင် MMS ပံ့ပိုးမှု
- ပေးသွင်းသူတိုင်း အလိုက် webhook လက်မှတ် စစ်ဆေးခြင်း

### Telegram

- Telegram Bot API
- မီဒီယာ ပံ့ပိုးမှု: ပုံများ၊ စာရွက်စာတမ်း၊ အသံမက်ဆေ့ချ်များ
- Inline keyboards နှင့် reply markup
- Webhook သို့မဟုတ် polling mode

### RCS (Rich Communication Services)

- Google RBM (Rich Business Messaging) API
- Rich cards၊ suggested actions၊ နှင့် carousels
- ပို့ဆောင်မှု နှင့် ဖတ်ရှုမှု receipts
- RCS မရရှိနိုင်သည့်နေရာတွင် SMS fallback

### Blast/Broadcast

အများပြည်သူ မက်ဆေ့ချ် ပို့ဆောင်ရန် PostgreSQL-အခြေခံ delivery queue:

- ရေဒီယိုတိုင်းအလိုက် rate limiting (ပေးသွင်းသူ ကန့်သတ်ချက်များကို လေးစား)
- အချိန်ဇုန် ပံ့ပိုးမှု နှင့် သတ်မှတ်ထားသော ပို့ဆောင်မှု
- လက်ခံသူတိုင်း အခြေအနေ ခြေရာခြင်း (စီတင်ထား၊ ပို့ထား၊ ရောက်ထား၊ ပျက်ထား)
- Dead-letter queue ဖြင့် ထပ်ကြိုးစားမှု
- ပြုပြင်နိုင်သော batch အရွယ်အစားများဖြင့် batch ပို့ဆောင်မှု
- အက်ဒမင် dashboard တွင် တိုက်ရိုက်ချိန် delivery အခြေအနေ ပြသခြင်း

## ဘက်စုံသုံး ပလက်ဖောင်း — အထူး အပ် ၃ ခု၊ Crypto Crate တစ်ခု

အများစု ပလက်ဖောင်းများသည် အင်တာနက် အပ်ကို အထူရာအထူး native wrapper အနည်းငယ်ဖြင့် ပို့သည်။ Llámenos သည် တစ်ခုတည်းသော စစ်ဆေးနိုင်သော Rust crypto အကောင်အထည်ကို မျှဝေသော အထူး အပ် ၃ ခု လုံးကို ပို့သည်။

### ဒက်စတော့ (Tauri v2)

- Windows၊ macOS၊ Linux native binaries
- သော့သိမ်းဆည်းရန် Tauri Stronghold ဝှက်စာထားသော vault
- ဝင်ရောက် ဖုန်းမြည်မှု အညွှန်း နှင့် native system tray
- Tauri updater ဖြင့် အလိုအလျောက် အပ်ဒိတ်
- တစ်ခုတည်း instance အတည်ပြုခြင်း
- Isolation pattern + Content Security Policy
- ဝှက်စာလုပ်ဆောင်ချက်အားလုံး Rust IPC မှတဆင့် လမ်းညွှန်သည် — ပုဂ္ဂလိကသော့များ ဘယ်တော့မှ webview ထဲ မဝင်ပါ
- E2E စမ်းသပ်ရန် PLAYWRIGHT_TEST တည်ဆောက်ပုံ mode နှင့် mock IPC layer

### iOS (SwiftUI)

- Native SwiftUI၊ iOS 17+ နှင့် `@Observable`
- သော့များကို iOS Keychain တွင် သိမ်း
- UniFFI XCFramework (`LlamenosCoreFFI`) မှတဆင့် Rust crypto
- XCTest + XCUITest ဖြင့် ယူနစ် နှင့် ပေါင်းစပ်မှု စမ်းသပ်မှု
- ဝှက်စာထားသော payload များဖြင့် APNs push notifications
- Multi-hub: နောက်ခံ handler များ ဘယ်တော့မှ active hub အခြေအနေကို မခွဲခြား

### Android (Kotlin/Compose)

- Native Kotlin 2.3 နှင့် Jetpack Compose၊ Material 3
- minSdk 26၊ AGP 9.1၊ Gradle 9.4
- EncryptedSharedPreferences မှတဆင့် Android Keystore တွင် သော့များ
- JNI shared library (`.so` ဖိုင်များ) မှတဆင့် Rust crypto — တူညီသော Rust crate မှ
- Hilt dependency injection + KSP annotation processing
- Compose UI စမ်းသပ်မှု + Cucumber BDD E2E စမ်းသပ်မှု
- Multi-hub: hub တစ်ခုချင်း ViewModel ပြန်လည်တင်ခြင်း၊ hub key caching၊ WebSocket လမ်းညွှန်

### မျှဝေထားသော Rust Crypto Crate

`packages/crypto/` သည် အောက်ပါအရာများကို အကောင်အထည်ဖော်ထားသည်:

- HPKE (RFC 9180): X25519-HKDF-SHA256-AES256-GCM
- Ed25519 လက်မှတ်များ (WebSocket ကိုက်ညီမှု အတွက် BIP-340 Schnorr)
- X25519 သော့ သဘောတူညီမှု
- PBKDF2 သော့ ထုတ်လုပ်မှု (၆၀၀K ကြိမ်)
- HKDF (RFC 5869)
- XChaCha20-Poly1305 အထောက်အထား ဝှက်စာ
- SFrame (RFC 9605) အသံ E2EE
- OpenMLS မှ MLS (Messaging Layer Security) — `mls` feature flag နောက်တွင်
- iOS/Android bindings အတွက် UniFFI scaffolding
- ဘရောက်ဆာ အသုံးပြုရန် WASM compilation

## အမှု စီမံခန့်ခွဲမှု

Llámenos သည် တစ်ခုခု သတ်မှတ်ထားသော အသုံးပြုမှု အခြေအနေကို မဟုတ်ဘဲ၊ template-driven ဖြစ်သည်။

**Template-driven အenties စနစ်** — အက်ဒမင်များသည် entity အမျိုးအစားများ (အဆက်အသွယ်များ၊ အမှုများ၊ အစီရင်ခံများ၊ အဖြစ်အပျက်များ)၊ ပြုပြင်ထားသော အကွက်များ (စာသား၊ နံပါတ်၊ ရွေးချယ်မှု၊ checkbox၊ textarea၊ ရက်စွဲ၊ ဖိုင်)၊ နှင့် report အမျိုးအစားများကို hub တစ်ခုချင်းစီ သတ်မှတ်နိုင်သည်။ Template များသည် ဖောင်အားလုံး နှင့် မြင်ကွင်းအားလုံး ကို လမ်းညွှန်သည်။ အလုပ်လုပ်ငန်းစဉ် အသစ်တစ်ခု ပြုပြင်ရန် ကုဒ်ပြောင်းစရာမလို။

**ပြုပြင်ထားသော report အမျိုးအစားများ** — Template များသည် `reportTypes[]` ကို သတ်မှတ်ပြီး၊ အမျိုးအစားတိုင်းအတွက် ပြုပြင်ထားသော အကွက်များ、`allowCaseConversion`၊ နှင့် `mobileOptimized` အလံတို့ ပါဝင်သည်။ Report အမျိုးအစားများသည် entity အမျိုးအစားများမှ လုံးဝကွဲပြားသည်။

**Blind-index ဝှက်စာ ရှာဖွေမှု** — မှတ်တမ်းများကို ဝှက်စာထားပြီး သိမ်းသည်၊ သို့သော် HMAC-indexed အကွက်များသည် ဆာဗာဘက်တွင် စာသားမဖော်ပြဘဲ ရှာဖွေနိုင်စေသည်။ Index များသည် hub တစ်ခုချင်းစီ အတွင်း သတ်မှတ်ထားပြီး၊ hub အကြား ဘယ်တော့မှ မရောယှက်ပါ။

**အဆက်အသွယ်များ နှင့် ဆက်ဆံပုံ** — ဆက်ဆံပုံ graph နှင့် အပြည့်အစုံ အဆက်အသွယ် directory။ အဆက်အသွယ်များကို အမှုများ၊ အဖြစ်အပျက်များ၊ နှင့် အထောက်အထားများသို့ ချိတ်ဆက်နိုင်သည်။ ဆက်ဆံပုံများသည် အမျိုးအစားခွဲထားသော (ဥပမာ၊ "သက်သေဖြစ်သည်"၊ "ဥပဒေရေးရာ လေ့လာသူဖြစ်သည်") နှင့် template တစ်ခုချင်းစီ ပြုပြင်နိုင်သော ဖြစ်သည်။

**အထောက်အထား စီမံခန့်ခွဲမှု** — အမှုများသို့ ဖိုင်များ တွဲဖက်နိုင်သည်။ ဖိုင်များကို အပ်လုဒ်မတိုင်မီ ဝှက်စာထားသည် (တာဝန်ခံဖတ်ရှုသူတိုင်း အတွက် HPKE-wrapped)။ အထောက်အထား လက်ဝယ်မှတ်တမ်း စစ်တမ်းတွင် မှတ်ပုံတင်ထားသည်။

**RBAC** — အခန်းကဏ္ဍ အခြေခံ ဝင်ခွင့်ထိန်းချုပ်မှု: စေတနာ့ဝန်ထမ်း (ကိုယ်ပိုင်မှတ်စုသာ)、အက်ဒမင် (ဒေတာအားလုံး)、သတင်းပို့သူ (တင်သွင်းချက်များသာ)။ Template တစ်ခုချင်းစီ ပြုပြင်နိုင်သော အခန်းကဏ္ဍများ။ အက်ဒမင်များသည် စေတနာ့ဝန်ထမ်းသာ ဖတ်နိုင်သော မှတ်စုများကို မမြင်နိုင်ပါ။

**Multi-hub** — Llámenos တပ်ဆင်မှုတစ်ခုသည် အဖွဲ့အစည်းများ၊ လိုင်းများ၊ သို့မဟုတ် အသုံးပြုမှု အခြေအနေများ အများအပြားကို ဝန်ဆောင်သည်။ အသုံးပြုသူတစ်ဦးသည် တစ်ချိန်တည်းတွင် hub အများအပြား၏ အဖွဲ့ဝင်ဖြစ်နိုင်သည်။ ဝင်ရောက်လာသော ဖုန်းခေါ်ဆိုမှု၊ အသိပေးချက်များ၊ နှင့် relay အဖြစ်အပျက်များအားလုံး အမြဲတမ်း လှုပ်ရှားနေသည် — လက်ရှိပြသနေသော hub အပေါ် မူတည်ခြင်းမရှိ။

## အထောက်အထား စစ်ဆေးခြင်း နှင့် သော့စီမံခန့်ခွဲမှု

**WebSocket သော့များ** — အသုံးပြုသူများသည် WebSocket-ကိုက်ညီသော Ed25519 သော့များဖြင့် အထောက်အထားစစ်ဆေးသည်။ BIP-340 Schnorr လက်မှတ် အတည်ပြုခြင်း။ စကားဝှက် မလို၊ အီးမေးလ် လိပ်စာ မလိုပါ။

**WebAuthn passkeys** — ဘက်စုံကိရိယာ လော့ဂ်အင်အတွက် ချိတ်ဆက်နိုင်သော passkey ပံ့ပိုးမှု။ ဟာ့ဒ်ဝဲ လုံခြုံမှုသော့ သို့မဟုတ် ပလက်ဖောင်း ဘዮမထရစ်ကို မှတ်ပုံတင်ပြီး၊ PIN မထည့်ဘဲ လက်မှတ်ထိုး ဝင်ရောက်နိုင်သည်။

**အသုံးပြုသူ sigchain** — Append-only၊ hash-chained ကိရိယာ တာဝန်ပေးမှု မှတ်တမ်းများ။ မှတ်တမ်းတိုင်းကို တာဝန်ပေးသော ကိရိယာ၏ Ed25519 သော့ဖြင့် လက်မှတ်ထိုးထားသည်။ အသုံးပြုသူတစ်ဦး အတွက် အထောက်အထားပေးထားသော ကိရိယာများ၏ ဝှက်စာဆိုင်ရာ သမိုင်းကို ပေးသည်။

**Cascading PUK rotation** — Per-User Key (PUK) → items_key → မှတ်စုတိုင်းအတွက် content key။ ကိရိယာ တစ်ခုခု တားမြစ်ခြင်း သို့မဟုတ် အသုံးပြုသူ PIN ပြောင်းသောအခါ၊ သက်ရောက်သော သော့များ lazily ပြန်လည်လည်ပတ် — မှတ်တမ်းများကို batch လုပ်ဆောင်ခြင်းမဟုတ်၊ ဝင်ရောက်သောအခါတိုင်း ပြန်လည်ဝှက်စာထားခြင်း။

**ကိရိယာ provisioning** — ပုဂ္ဂလိကသော့ မဖော်ပြဘဲ ကိရိယာအသစ်များ ချိတ်ဆက်နိုင်သည်။ QR ကုဒ် စကင်န်ဖတ်ခြင်း သို့မဟုတ် တိုတိုသော provisioning ကုဒ် ထည့်သွင်းခြင်း။ ယာယီ ECDH သော့ လဲလှယ်ခြင်း ကို သုံးသည်။ Provisioning room များ မိနစ် ၅ အတွင်း သက်တမ်းကုန်။

**ပြန်လည်ရရှိရေး သော့များ** — စတင်သုံးစဉ် Base32 ပုံစံ ပြန်လည်ရရှိရေး သော့ (၁၂၈-ဘစ် entropy) ထုတ်လုပ်သည်။ ဆက်သွားမီ မဖြစ်မနေ ဝှက်စာထားသော backup ဒေါင်းလုဒ် လုပ်ရန်။ ဒီသော့မှသာ ပြန်လည်ရရှိနိုင် — အက်ဒမင် ပြန်လည်ရရှိရေး မရှိ၊ ဒီဇိုင်းအရ။

**အလိုအလျောက် လော့ခ်** — သော့စီမံခန့်ခွဲသူသည် အလုပ်မလုပ်တာ အချိန်ကုန်သောအခါ သို့မဟုတ် ဘရောက်ဆာ tab ကို ဖွင့်ထားခြင်း မရှိသောအခါ အလိုအလျောက် လော့ခ်ဖြစ်သည်။ ပြုပြင်နိုင်သော အလုပ်မလုပ်တာ ကြာချိန်။ ပြန်ဖွင့်ရန် PIN ထည့်ရန်။

**Session မော်ဒယ်** — နှစ်ဆင့်: "authenticated but locked" (session token သာ၊ ဖတ်ရှုမှုတည်း ကြည့်ခွင့်) နှင့် "authenticated and unlocked" (PIN ထည့်ထား၊ ဝှက်စာ အပြည့်အစုံ ဝင်ခွင့်)။ ၈-နာရီ session token များ နှင့် အလုပ်မလုပ်တာ အချိန်ကုန်မှု သတိပေးချက်များ။

## တိုက်ရိုက်ချိန် အခြေခံအဆောက်အအုံ

**WebSocket relay** — တိုက်ရိုက်ချိန် အဖြစ်အပျက်ဖြန့်ဝေရန် ကိုယ်ပိုင် ဟော့စ် WebSocket relay (သို့မဟုတ် Cloudflare ပေါ် Nosflare)။ အဖြစ်အပျက် အကြောင်းအရာအားလုံး hub key ဖြင့် ဝှက်စာထားသည်။ Generic tags (`["t", "llamenos:event"]`) သည် relay အဆင့်တွင် အဖြစ်အပျက် အမျိုးအစားများအကြောင်း metadata ခန့်မှန်းခြင်းကို တားဆီးသည်။

**Hub key** — ကျပန်း ၃၂ ဘိုက် (`crypto.getRandomValues`)၊ `LABEL_HUB_KEY_WRAP` ဖြင့် hub အဖွဲ့ဝင်တိုင်း အတွက် သီးခြား HPKE-wrapped။ အဖွဲ့ဝင် ထွက်ခွာသောအခါ ပြန်လည်လည်ပတ် — ထွက်ခွာသော အဖွဲ့ဝင် အနာဂတ် အဖြစ်အပျက်များကို မဖွင့်နိုင်။

**WebSocket** — တိုက်ရိုက်ချိန် ဖုန်းအခြေအနေ၊ စေတနာ့ဝန်ထမ်း ရှိနေမှု၊ စကားပြောဆိုမှု အပ်ဒိတ်များ၊ နှင့် အက်ဒမင် စောင့်ကြည့်မှု WebSocket မှတဆင့်။ Exponential backoff ဖြင့် ပြန်လည်ချိတ်ဆက်မှု။

**WebSocket တိုက်ရိုက်ချိန် sync** — ဘက်စုံကိရိယာ နှင့် ဘက်စုံသုံး hub အခြေအနေ တူညီစေရန် ယာယီ kind 20001 အဖြစ်အပျက်များ။ အကြောင်းအရာ ဝှက်စာထား၊ relay သည် အဖြစ်အပျက် အမျိုးအစားကို ခွဲခြား မရ။

## အက်ဒမင် နှင့် စေတနာ့ဝန်ထမ်း အတွေ့အကြုံ

**Setup wizard** — ပထမဆုံး အက်ဒမင် လော့ဂ်အင်တွင် လမ်းညွှန်ထားသော အဆင့် အများအပြား။ ရေဒီယိုများ ရွေးချယ်၊ ပေးသွင်းသူများ ပြုပြင်၊ အပူပိုင်းလိုင်း အမည် သတ်မှတ်။ အစပြု hub keypair ထုတ်လုပ်ပြီး ပထမဆုံး အက်ဒမင်သို့ hub key ဖြန့်ဝေ။

**စတင်သုံးခြင်း စစ်ရန်** — Dashboard widget သည် setup အခြေအနေ ခြေရာခြင်း: ရေဒီယို ပြုပြင်မှု၊ စေတနာ့ဝန်ထမ်း onboard မှု၊ လှည့်ကိုင် ဖန်တီးမှု။

**တိုက်ရိုက်ချိန် စောင့်ကြည့်မှု** — လှုပ်ရှားနေသော ဖုန်းခေါ်ဆိုမှု၊ စီတင်ထားသော ခေါ်ဆိုသူများ၊ စကားပြောဆိုမှုများ၊ နှင့် စေတနာ့ဝန်ထမ်း အခြေအနေ WebSocket ဖြင့် တိုက်ရိုက်ချိန် အပ်ဒိတ်။

**Command palette** — Ctrl+K (သို့မဟုတ် Cmd+K) ဖြင့် ချက်ချင်း လမ်းညွှန်၊ ရှာဖွေ၊ မှတ်စု အမြန်ဖန်တီး၊ နှင့် အသွင်အပြင် ပြောင်းခြင်း။ အက်ဒမင်-သာ command များ အခန်းကဏ္ဍဖြင့် စစ်ထုတ်။

**စေတနာ့ဝန်ထမ်း ရှိနေမှု** — အက်ဒမင်များသည် တိုက်ရိုက်ချိန် online/offline/on-break အရေအတွက်ကို မြင်နိုင်သည်။ စေတနာ့ဝန်ထမ်းများသည် break switch ကို toggle လုပ်၍ လှည့်ကိုင် မထွက်ဘဲ ဝင်ရောက် ဖုန်းများကို ခေတ္တရပ်နိုင်သည်။

**ကီးဘုတ် အမြှောက်** — `?` နှိပ်ပါ အမြှောက်အားလုံး။ စာမျက်နှာများ လမ်းညွှန်၊ command palette ဖွင့်၊ မက်စ်မလို အသုံးဝင်သော လုပ်ဆောင်ချက်များ။

**မှောင်/အလင်း အသွင်အပြင်** — စနစ်-အလိုက်၊ မှောင်၊ သို့မဟုတ် အလင်း။ Session တစ်ခုချင်းစီ သိမ်း။

**GDPR ဒေတာ ထုတ်ယူမှု** — မှတ်စုများကို GDPR-ကိုက်ညီသော ဝှက်စာထားသော ဖိုင် (`.enc`) အဖြစ် ထုတ်ယူနိုင်သည်။ မူရင်းရေးသားသူသာ ဖွင့်နိုင်သည်။

## နိုင်ငံတကာအသုံးပြုမှု (i18n)

**ဖန်တီးထားသော ဘာသာစကား ၁၃ ခု** — English、Español (စပိန်)、中文 (တရုတ်)、Tagalog、Tiếng Việt (ဗီယက်နမ်)、العربية (အာရဗီ၊ RTL)、Français (ပြင်သစ်)、Kreyòl Ayisyen (ဟေတီ)、한국어 (ကိုရီးယား)、Русский (ရုရှား)、हिन्दी (ဟိန္ဒီ)、Português (ပေါ်တူဂီ)、Deutsch (ဂျာမန်)။

**Codegen ပိုင်းစဉ်** — JSON locale ဖိုင်များတွင် တစ်ခုတည်းသော အရင်းအမြစ် မှ iOS `.strings`၊ Android `strings.xml`၊ နှင့် Kotlin `I18n.kt` ထုတ်လုပ် — လက်ဖြင့် sync လုပ်ရန် မလို။ `bun run i18n:validate:all` ဖြင့် အတည်ပြု။

**RTL ပံ့ပိုးမှု** — အာရဗီ အသွင်အပြင်သည် RTL mode တွင် မှန်ကန်စွာ ပုံဖော်ပြီး၊ ပြောင်းပြန် လမ်းညွှန်၊ စာသား အညီညာမှု ပြုပြင်ထား၊ နှင့် ဘက်နှစ်ဖက်စာ ကိုင်တွယ်မှု။

**ဘာသာစကားတိုင်း ပြုပြင်ထားသော IVR prompts** — ခေါ်ဆိုသူများ အသုံးပြုသော ဘာသာစကားတိုင်းအတွက် အသံ prompts မှတ်တမ်းတင်နိုင်သည်။ မှတ်တမ်းမရှိသောအခါ text-to-speech သို့ fallback။

## တပ်ဆင်မှု

### Docker Compose (တစ်ခုတည်း ဆာဗာ)

- အပြည့်အစုံ stack: Bun HTTP server၊ PostgreSQL၊ RustFS (object storage)、WebSocket relay
- ရွေးချယ်နိုင်သော profiles: `--profile signal` (signal-cli sidecar)、`--profile telephony` (Kamailio + CoTURN)、`--profile inference` (LLM firehose agent)、`--profile monitoring` (Prometheus + Grafana)
- `docker-compose.dev.yml` သည် file watching ဖြင့် ဒေသန္တရ ဖွံ့ဖြိုးမှု အတွက်
- `docker-compose.production.yml` overlay သည် ထုတ်လုပ်မှု ခိုင်မာစေရန်

### Kubernetes (Helm)

- ပြုပြင်နိုင်သော replicas ဖြင့် ထုတ်လုပ်မှု Helm chart
- ကျန်းမာရေး probes: `/health/ready` နှင့် `/health/live`
- Metrics scraping အတွက် Prometheus ServiceMonitor
- HSTS၊ CSP၊ နှင့် လုံခြုံရေး header များဖြင့် Caddyfile.production
- တပ်ဆင်မှု မတိုင်မီ အတည်ပြုရန် Ansible preflight + smoke-check playbooks

### Co-op Cloud

- Co-op Cloud တပ်ဆင်မှုများအတွက် recipe
- ကိုယ်ပိုင် အခြေခံအဆောက်အအုံ လည်ပတ်သော အလုပ်သမား co-op များ နှင့် အသိုင်းအဝိုင်း အဖွဲ့အစည်းများအတွက် တည်ဆောက်ထား

### Cloudflare Tunnels

- Cloudflare Tunnels မှတဆင့် ဝင်ရောက်မှု — ဝင်ရောက် inbound port များ မဖွင့်ရန် လိုအပ်
- NAT နောက်က ကိုယ်ပိုင် ဟော့စ်တင်ဆာဗာများနှင့် ကိုက်ညီ
- EU-ဟော့စ်တင် VPS နှင့် ပေါင်းစပ်သောအခါ EU/GDPR-ကိုက်ညီသော ဒေတာ နေရာထိုင်ခင်း

### GDPR ကိုက်ညီမှု

- ဒေတာများကို သင့်ဆာဗာများတွင် သိမ်း (သို့မဟုတ် EU-အခြေခံ VPS)
- ဖျက်သိမ်းခွင့်: အက်ဒမင်သည် ခေါ်ဆိုသူ မှတ်တမ်းများ၊ မှတ်စုများ၊ နှင့် မှတ်တမ်းများကို ရှင်းလင်းနိုင်သည်
- GDPR-ကိုက်ညီသော ဝှက်စာထားသော ဒေတာ ထုတ်ယူမှု
- အပ်ပ် တွင်တိုင် တတိယပါတီ ခြေရာခြင်း သို့မဟုတ် analytics မရှိ

## Signal အသိပေးမှု Sidecar

`signal-notifier/` သည် port 3100 တွင် သီးခြား လုပ်ငန်းစဉ်အဖြစ် လည်ပတ်သည်။ ၎င်း **zero-knowledge**: အဆက်အသွယ်များကို HMAC-ဟက်ချ်ထားသော အထောက်အထားများ ဖြင့် ဖြေရှင်း — sidecar သည် စာသားပုံစံ ဖုန်းနံပါတ်များ ဘယ်တော့မှ မသိမ်း။ `SIGNAL_NOTIFIER_BEARER_TOKEN` သည် အဓိက အပ်မှ sidecar သို့ အထောက်အထားစစ်ဆေးရန် မျှဝေထားသည်။

## ပရိုတိုကော် နှင့် Codegen

အမျိုးအစားအားလုံးသည် တစ်ခုတည်းသော အရင်းအမြစ်မှ စီးဆင်း:

- `packages/protocol/schemas/` ရှိ **Zod schemas** သည် API နှင့် wire အမျိုးအစားအားလုံး သတ်မှတ်
- **Codegen** (`bun run codegen`) သည် Swift Codable structs၊ Kotlin `@Serializable` data classes၊ နှင့် OpenAPI snapshot ထုတ်လုပ်
- `packages/protocol/crypto-labels.json` ရှိ **Crypto labels** (၅၇ ခု) သည် TypeScript၊ Swift၊ နှင့် Kotlin သို့ ထုတ်လုပ် — ဝှက်စာ ကုဒ်တွင် ကျပန်းစာကြောင်း မရှိ
- **i18n codegen** (`bun run i18n:codegen`) သည် JSON locale ဖိုင်များမှ iOS `.strings`၊ Android `strings.xml`၊ နှင့် Kotlin `I18n.kt` ထုတ်လုပ်

ဤအရာအတွက် schema သို့မဟုတ် ပရိုတိုကော် ပြောင်းလဲမှုတိုင်းသည် အလိုအလျောက် သုံးခုလုံး ပလက်ဖောင်းသို့ ပျံ့နှံ့သည်။
