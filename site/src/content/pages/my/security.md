## သင့်ဟော့စတင်ဝန်ဆောင်မှုပေးသူကိုတရားရုံးဆင့်ခေါ်စာရရှိပါက

| ၎င်းတို့ပေးနိုင်သည် | ၎င်းတို့မပေးနိုင် |
|---|---|
| ခေါ်ဆိုမှု/မက်ဆေ့ချ်မက်တာဒေတာ (အချိန်များ၊ ကြာချိန်များ) | မှတ်စုပါအကြောင်းအရာ၊ စကားဝိုင်းမှတ်တမ်းများ၊ အစီရင်ခံစာကိုယ်ထည်များ |
| ကုဒ်ဝှက်ထားသောဒေတာဘေ့စ် blobs | စေတနာ့ဝန်ထမ်းအမည်များ (အဆုံးမှအဆုံးကုဒ်ဝှက်ထား) |
| မည်သည့်စေတနာ့ဝန်ထမ်းအကောင့်များတက်ကြွခဲ့သည်ကို | အဆက်အသွယ်လမ်းညွှန်မှတ်တမ်းများ (အဆုံးမှအဆုံးကုဒ်ဝှက်ထား) |
| ထုတ်လွှင့်မက်ဆေ့ချ်ပို့ဆောင်မှုမှတ်တမ်းများ | မက်ဆေ့ချ်ပါအကြောင်းအရာ (ရောက်ရှိချိန်တွင်ကုဒ်ဝှက်ထား၊ ciphertext အဖြစ်သိမ်းဆည်းထား) |
| | ကုဒ်ဖော်သော့များ (သင့် PIN၊ သင့်အထောက်အထားဝန်ဆောင်မှုပေးသူအကောင့်နှင့် ချန်လှပ်ပါကသင့်ဟာ့ဒ်ဝဲလုံခြုံရေးသော့ဖြင့်ကာကွယ်ထား) |
| | မှတ်စုတစ်ခုချင်းသော့များ (ခဏတာ — ထုပ်ပိုးပြီးနောက်ဖျက်ဆီးပစ်) |
| | ဖုန်းနံပါတ် hashes များကိုပြောင်းပြန်လှန်ရန်သင့် HMAC လျှို့ဝှက်ချက် |
| | ပြန်လည်ရယူရေးမျှဝေမှုပါအကြောင်းအရာ (ကုဒ်ဝှက်ထား၊ ဆာဗာကမဖတ်နိုင်) |

**ဆာဗာသည်မဖတ်နိုင်သောဒေတာကိုသိမ်းဆည်းသည်။** မက်တာဒေတာ (ဘယ်အချိန်၊ ဘယ်လောက်ကြာ၊ မည်သည့်အကောင့်များ) ကိုမြင်နိုင်သည်။ အကြောင်းအရာ (ဘာပြောခဲ့၊ ဘာရေးခဲ့၊ သင့်အဆက်အသွယ်များမည်သူ) ကိုမမြင်နိုင်ပါ။

## အင်္ဂါရပ်အလိုက်

သင့်ကိုယ်ရေးလုံခြုံမှုထိတွေ့မှုသည် သင်ဖွင့်ထားသည့်ချန်နယ်များပေါ်တွင်မူတည်သည်-

### အသံခေါ်ဆိုမှုများ

| သင်အသုံးပြုပါက... | တတိယပါတီများဝင်ရောက်နိုင် | ဆာဗာဝင်ရောက်နိုင် | အဆုံးမှအဆုံးကုဒ်ဝှက်ထားသောအကြောင်းအရာ |
|---|---|---|---|
| Twilio/SignalWire/Vonage/Plivo | ခေါ်ဆိုမှုအသံ (တိုက်ရိုက်), ခေါ်ဆိုမှုမှတ်တမ်းများ | ခေါ်ဆိုမှုမက်တာဒေတာ | မှတ်စုများ၊ စကားဝိုင်းမှတ်တမ်းများ |
| ကိုယ်တိုင်လက်ခံဆောင်ရွက်ထားသော Asterisk | ဘာမှမရ (သင်ထိန်းချုပ်သည်) | ခေါ်ဆိုမှုမက်တာဒေတာ | မှတ်စုများ၊ စကားဝိုင်းမှတ်တမ်းများ |
| ဘရောက်ဆာမှဘရောက်ဆာ (WebRTC) | ဘာမှမရ | ခေါ်ဆိုမှုမက်တာဒေတာ | မှတ်စုများ၊ စကားဝိုင်းမှတ်တမ်းများ |

**တယ်လီဖုန်းဝန်ဆောင်မှုပေးသူတရားရုံးဆင့်ခေါ်စာ**: ၎င်းတို့တွင် ခေါ်ဆိုမှုအသေးစိတ်မှတ်တမ်းများ (အချိန်များ၊ ဖုန်းနံပါတ်များ၊ ကြာချိန်များ) ရှိသည်။ ၎င်းတို့တွင် ခေါ်ဆိုမှုမှတ်စုများ သို့မဟုတ် စကားဝိုင်းမှတ်တမ်းများ **မရှိပါ**။ မှတ်တမ်းတင်ခြင်းကိုပုံမှန်အားဖြင့်ပိတ်ထားသည်။

**စကားဝိုင်းမှတ်တမ်း**: စကားဝိုင်းမှတ်တမ်းသည် သင့်ဘရောက်ဆာတွင် စက်ပေါ်ရှိ AI ကိုအသုံးပြု၍ လုံးဝဖြစ်ပေါ်သည်။ **အသံသည် သင့်စက်ပစ္စည်းမှဘယ်တော့မျှမထွက်ခွာပါ။** ကုဒ်ဝှက်ထားသောစကားဝိုင်းမှတ်တမ်းကိုသာသိမ်းဆည်းသည်။

### စာတိုပေးပို့ခြင်း (တစ်ဦးချင်း)

| ချန်နယ် | ဝန်ဆောင်မှုပေးသူဝင်ရောက်ခွင့် | ဆာဗာသိုလှောင်မှု | မှတ်ချက်များ |
|---|---|---|---|
| SMS | သင့်တယ်လီဖုန်းဝန်ဆောင်မှုပေးသူကမက်ဆေ့ချ်အားလုံးကိုဖတ်သည် | **ကုဒ်ဝှက်ထား** | ဝန်ဆောင်မှုပေးသူကမူရင်းမက်ဆေ့ချ်များကိုထိန်းသိမ်းထား |
| WhatsApp | Meta ကမက်ဆေ့ချ်အားလုံးကိုဖတ်သည် | **ကုဒ်ဝှက်ထား** | ဝန်ဆောင်မှုပေးသူကမူရင်းမက်ဆေ့ချ်များကိုထိန်းသိမ်းထား |
| Signal | Signal ကွန်ရက်သည်အဆုံးမှအဆုံးကုဒ်ဝှက်ထား; bridge ကရောက်ရှိချိန်တွင်ပြန်လည်ကုဒ်ဝှက်သည် | **ကုဒ်ဝှက်ထား** | ရရှိနိုင်ပါကဦးစားပေးလမ်းကြောင်း |

**Signal-ဦးစားပေးပို့ဆောင်မှု**: လက်ခံသူတွင် Signal ရှိပါက မက်ဆေ့ချ်များကို Signal မှတစ်ဆင့်အလိုအလျောက်လမ်းကြောင်းသတ်မှတ်သည် — သင့်တယ်လီဖုန်းဝန်ဆောင်မှုပေးသူက အကြောင်းအရာကိုဘယ်တော့မျှမမြင်ပါ။ SMS အတွက်ပုံမှန်အားဖြင့် "သင့်တွင်မက်ဆေ့ချ်အသစ်ရှိသည်" ဟူသော ယေဘုယျအကြောင်းကြားချက်ကိုသာပို့သည် (မက်ဆေ့ချ်ကိုယ်ထည်မပါ)၊ ထို့ကြောင့်သင့်ဝန်ဆောင်မှုပေးသူ၏မှတ်တမ်းများတွင် ထိလွယ်ရှလွယ်အကြောင်းအရာမပါဝင်ပါ။

**မက်ဆေ့ချ်များသည်သင့်ဆာဗာသို့ရောက်ရှိသည့်အချိန်တွင်ကုဒ်ဝှက်ခြင်းခံရသည်။** ဆာဗာသည် ciphertext ကိုသာသိမ်းဆည်းသည်။ သင့်တယ်လီဖုန်း သို့မဟုတ် မက်ဆေ့ချ်ဝန်ဆောင်မှုပေးသူတွင် မူရင်းမက်ဆေ့ချ်ရှိနေနိုင်ဆဲဖြစ်သည် — ၎င်းသည် ထိုပလက်ဖောင်းများ၏ကန့်သတ်ချက်တစ်ခုဖြစ်ပြီး ကျွန်ုပ်တို့ပြောင်းလဲနိုင်သောအရာမဟုတ်ပါ။

**မက်ဆေ့ချ်ဝန်ဆောင်မှုပေးသူတရားရုံးဆင့်ခေါ်စာ**: SMS ဝန်ဆောင်မှုပေးသူများသည် သင်အကြောင်းအရာအပြည့်အစုံ SMS mode ကိုရှင်းလင်းစွာဖွင့်မှသာ မက်ဆေ့ချ်အပြည့်အစုံကိုရရှိသည်။ ပုံမှန်အကြောင်းကြားချက်သာ mode ဖြင့် SMS ကိုယ်ထည်များတွင် မက်ဆေ့ချ်ပါအကြောင်းအရာမပါဝင်ပါ။ Meta တွင် WhatsApp အကြောင်းအရာရှိသည်။ Signal မက်ဆေ့ချ်များသည် bridge သို့အဆုံးမှအဆုံးကုဒ်ဝှက်ထားသော်လည်း bridge (သင့်ဆာဗာတွင်လည်ပတ်သည်) က ၎င်းတို့ကိုသိုလှောင်ရန်ပြန်လည်မကုဒ်ဝှက်မီ ကုဒ်ဖော်သည်။ ကိစ္စအားလုံးတွင် **သင့်ဆာဗာတွင် ciphertext သာရှိသည်** — ဟော့စတင်ဝန်ဆောင်မှုပေးသူသည် မက်ဆေ့ချ်ပါအကြောင်းအရာကိုမဖတ်နိုင်ပါ။

### အစုလိုက်နှင့်ထုတ်လွှင့်မက်ဆေ့ချ်များ

အက်ဒမင်များသည် SMS, WhatsApp, Signal သို့မဟုတ် RCS မှတစ်ဆင့် စာရင်းသွင်းသူများသို့ ထုတ်လွှင့်မက်ဆေ့ချ်များကိုပို့နိုင်သည်။

**အရေးကြီး: အထွက်ထုတ်လွှင့်မက်ဆေ့ချ်များသည်ဆာဗာတွင်အဆုံးမှအဆုံးကုဒ်ဝှက်မထားပါ။** SMS သို့မဟုတ် WhatsApp စာရင်းသွင်းသူများသို့မက်ဆေ့ချ်ပို့ရန် ဆာဗာသည် ရိုးရိုးစာသားပါအကြောင်းအရာကိုခဏတာလုပ်ဆောင်ပြီး မက်ဆေ့ချ်ဝန်ဆောင်မှုပေးသူသို့ပေးအပ်ရမည်။ ထို့နောက်ဝန်ဆောင်မှုပေးသူကပို့ဆောင်ပြီး မိတ္တူကိုထိန်းသိမ်းထားနိုင်သည်။

| ချန်နယ် | ပို့စဉ်ဆာဗာဝင်ရောက်ခွင့် | ဝန်ဆောင်မှုပေးသူဝင်ရောက်ခွင့် | ပို့ပြီးနောက် |
|---|---|---|---|
| SMS blast | ရိုးရိုးစာသား (ခဏတာ၊ ပို့ဆောင်ရန်အတွက်) | မက်ဆေ့ချ်အပြည့်အစုံ | ဝန်ဆောင်မှုပေးသူကထိန်းသိမ်း |
| WhatsApp blast | ရိုးရိုးစာသား (ခဏတာ၊ ပို့ဆောင်ရန်အတွက်) | မက်ဆေ့ချ်အပြည့်အစုံ (Meta) | ဝန်ဆောင်မှုပေးသူကထိန်းသိမ်း |
| Signal blast | ရိုးရိုးစာသား (ခဏတာ၊ ပို့ဆောင်ရန်အတွက်) | Signal ကွန်ရက်မှတစ်ဆင့်အဆုံးမှအဆုံးကုဒ်ဝှက် | ဝန်ဆောင်မှုပေးသူကမထိန်းသိမ်း |
| RCS blast | ရိုးရိုးစာသား (ခဏတာ၊ ပို့ဆောင်ရန်အတွက်) | Google ကအကြောင်းအရာကိုမြင်နိုင် | ဝန်ဆောင်မှုပေးသူကထိန်းသိမ်း |

**ဤဆိုလိုချက်**: ထုတ်လွှင့်မက်ဆေ့ချ်များတွင် ထိလွယ်ရှလွယ်သောခေါ်ဆိုသူအချက်အလက်များမပါဝင်သင့်ပါ။ ၎င်းတို့ကိုကြေညာချက်များ၊ အချိန်ဇယားအကြောင်းကြားချက်များနှင့်အရင်းအမြစ်များအတွက်သုံးပါ — အမှုအသေးစိတ်များ သို့မဟုတ် ခေါ်ဆိုသူများသို့မဟုတ်စေတနာ့ဝန်ထမ်းများကိုခွဲခြားသတ်မှတ်နိုင်သည့်မည်သည့်အရာအတွက်မျှမသုံးပါနှင့်။

စာရင်းသွင်းသူဖုန်းနံပါတ်များကို hash လုပ်ထားသောအညွှန်းများအဖြစ်သိမ်းဆည်းသည် — သင့်ဒေတာဘေ့စ်တွင် ရိုးရိုးစာသားစာရင်းသွင်းသူစာရင်း ဘယ်တော့မျှမပါဝင်ပါ။ ငြင်းဆိုခြင်း (STOP) တောင်းဆိုချက်များကိုချက်ချင်းလုပ်ဆောင်ပြီး စာရင်းသွင်းသူအခြေအနေကိုအပ်ဒိတ်လုပ်သည်။

### မှတ်စုများ၊ စကားဝိုင်းမှတ်တမ်းများနှင့်အစီရင်ခံစာများ

စေတနာ့ဝန်ထမ်းရေးသားသည့်အကြောင်းအရာအားလုံးသည် အဆုံးမှအဆုံးကုဒ်ဝှက်ထားသည်-

- မှတ်စုတစ်ခုစီသည် **ထူးခြားသောကျပန်းသော့** ကိုအသုံးပြုသည် (ရှေ့သွားလျှို့ဝှက်မှု — မှတ်စုတစ်ခုကိုအလျှော့ပေးခြင်းသည် အခြားမှတ်စုများကိုမထိခိုက်စေပါ)
- သော့များကိုစေတနာ့ဝန်ထမ်းနှင့်အက်ဒမင်တစ်ဦးချင်းစီအတွက်သီးခြားထုပ်ပိုးထား
- ဆာဗာသည် ciphertext ကိုသာသိမ်းဆည်းသည်
- ကုဒ်ဖော်ခြင်းသည်သင့်စက်ပစ္စည်းပေါ်တွင် အက်ပ်၏အသုံးပြုသူမျက်နှာပြင်သို့သော့များကိုဘယ်တော့မျှမထုတ်ဖော်သောလုံခြုံသောအလွှာတွင်ဖြစ်ပေါ်သည်
- **စိတ်ကြိုက်အကွက်များ၊ အစီရင်ခံစာပါအကြောင်းအရာနှင့်ဖိုင်ပူးတွဲမှုများအားလုံးကိုတစ်ခုချင်းကုဒ်ဝှက်ထား**

**အမှုမှတ်တမ်းများနှင့်အဖွဲ့အစည်းဒေတာ**: ဖွဲ့စည်းထားသောအမှုမှတ်တမ်းများ (အဆက်အသွယ်များ၊ အမှုများ၊ သက်သေကွင်းဆက်များ) သည် တူညီသောကုဒ်ဝှက်ပုံစံအတိုင်းလိုက်နာသည် — ပစ္စည်းတစ်ခုစီကိုထူးခြားသောသော့ဖြင့်ကုဒ်ဝှက်ထားပြီး ခွင့်ပြုထားသောကြည့်ရှုသူများအတွက်ထုပ်ပိုးထားသည်။ ဆာဗာသည်အမှုပါအကြောင်းအရာကိုမဖတ်နိုင်ပါ။

**စက်ပစ္စည်းသိမ်းယူခြင်း**: သင့် PIN **နှင့်** သင့်အထောက်အထားဝန်ဆောင်မှုပေးသူအကောင့်သို့ဝင်ရောက်ခွင့်မရှိပါက တိုက်ခိုက်သူများသည် Argon2id — မှတ်ဉာဏ်ခိုင်မာသောသော့ဆင်းသက်ခြင်းလုပ်ဆောင်ချက်ဖြင့်ကာကွယ်ထားသော ကုဒ်ဝှက်ထားသော blob ကိုရရှိသည် — ၎င်းသည် အထူးပြုဟာ့ဒ်ဝဲ (GPU, ASIC) ဖြင့် brute-force တိုက်ခိုက်မှုများကို ရိုးရာနည်းလမ်းများထက်အဆများစွာပိုမိုစျေးကြီးစေသည်။ သင်သည်ဟာ့ဒ်ဝဲလုံခြုံရေးသော့ကိုလည်းအသုံးပြုပါက သင့်ဒေတာကိုကာကွယ်ရန် **လွတ်လပ်သောအချက်သုံးချက်** ရှိသည်။

## သင့်စက်ပစ္စည်းများ

### စက်ပစ္စည်းများကိုကြည့်ရှုခြင်းနှင့်ပြန်လည်ရုပ်သိမ်းခြင်း

အက်ပ်သည်သင်အကောင့်ဝင်ခဲ့သည့်စက်ပစ္စည်းတိုင်း၏စာရင်းကိုထားရှိသည်။ ဤစာရင်းကိုသင်ကြည့်ရှုနိုင်ပြီး သင်မမှတ်မိသည့်မည်သည့်စက်ပစ္စည်းကိုမဆိုပြန်လည်ရုပ်သိမ်းနိုင်သည်။

**စက်ပစ္စည်းတစ်ခုကိုပြန်လည်ရုပ်သိမ်းသည့်အခါ-**
- ထိုစက်ပစ္စည်းသည်သင့်အကောင့်သို့ဝင်ရောက်ခွင့်မှချက်ချင်းပိတ်ဆို့ခံရသည်
- သင့်ကုဒ်ဝှက်သော့များကိုလှည့်ပြောင်းထားသောကြောင့် ပြန်လည်ရုပ်သိမ်းထားသောစက်ပစ္စည်းသည်နောင်အကြောင်းအရာများကိုကုဒ်ဖော်နိုင်တော့မည်မဟုတ်ပါ
- ပြန်လည်ရုပ်သိမ်းခြင်းကိုသင့်အကောင့်၏လုံခြုံရေးမှတ်တမ်းတွင်မှတ်တမ်းတင်ထားသည်

ဆိုလိုသည်မှာ တစ်စုံတစ်ယောက်တွင် ပြန်လည်ရုပ်သိမ်းခြင်းမတိုင်မီကသင့်ကုဒ်ဝှက်ထားသောဒေတာမိတ္တူရှိလျှင်တောင် ၎င်းတို့သည်ပြန်လည်ရုပ်သိမ်းပြီးနောက်ဖန်တီးထားသောအကြောင်းအရာအသစ်ကိုမဖတ်နိုင်ပါ။

### SAS emoji အတည်ပြုခြင်း

လုံခြုံရေးလိုအပ်ချက်မြင့်မားသောအဖွဲ့အစည်းများအတွက် အက်ဒမင်များသည် SAS (တိုတောင်းသောစစ်မှန်ကြောင်းအထောက်အထားပြစာကြောင်း) အတည်ပြုခြင်းကိုအသုံးပြု၍ စက်ပစ္စည်းတစ်ခု၏အထောက်အထားကိုအတည်ပြုနိုင်သည် — emoji ၇ လုံးအစီအစဉ်အဖြစ်ပြသထားသည်။

**မည်သို့အလုပ်လုပ်သည်-**
၁။ အက်ဒမင်နှင့်စက်ပစ္စည်းပိုင်ရှင်သည် ၎င်းတို့၏ emoji အစီအစဉ်များကိုနှိုင်းယှဉ်သည် (လူကိုယ်တိုင်၊ ဖုန်းဖြင့် သို့မဟုတ် ယုံကြည်ရသောချန်နယ်မှတစ်ဆင့်)
၂။ emoji များတူညီပါက စက်ပစ္စည်းသည် ၎င်း၏မှတ်ပုံတင်ထားသောပိုင်ရှင်နှင့်သက်ဆိုင်ကြောင်းအတည်ပြုသည်
၃။ အတည်ပြုချက်ကိုမှတ်တမ်းတင်သည် — အက်ဒမင်များသည်မည်သည့်စက်ပစ္စည်းများကိုအတည်ပြုထားသည်ကိုမြင်နိုင်သည်

၎င်းသည် အခြားသူတစ်ဦး၏အကောင့်အောက်တွင် စက်ပစ္စည်းအတုတစ်ခုမှတ်ပုံတင်ထားသော တိုက်ခိုက်သူတစ်ဦးကိုကာကွယ်ပေးသည်။ emoji အစီအစဉ်သည် စက်ပစ္စည်းနှစ်ခုလုံး၏ကုဒ်ဝှက်ဆိုင်ရာအထောက်အထားသော့များနှင့် တစ်ကြိမ်သုံးကုဒ်တစ်ခုမှဆင်းသက်လာသည် — ဆာဗာက၎င်းကိုချိန်ညှိနိုင်ခြင်းမရှိ သို့မဟုတ် ကြိုတင်ခန့်မှန်း၍မရပါ။

## အကောင့်ဖျက်ခြင်း

### ကိုယ်တိုင်လုပ်ဆောင်သည့်ဖျက်ခြင်း

သင့်အကောင့်နှင့်ဆက်စပ်ဒေတာအားလုံးကိုအပြီးတိုင်ဖျက်ရန်တောင်းဆိုနိုင်သည်။ ပုံမှန်အားဖြင့် ဖျက်ခြင်းမပြီးဆုံးမီ နှောင့်နှေးမှုတစ်ခု (သင့် hub အက်ဒမင်ကသတ်မှတ်သည်၊ ပုံမှန်အားဖြင့် ၇၂ နာရီ) ရှိသည် — ၎င်းသည်တောင်းဆိုမှုကိုအတင်းအကျပ်ပြုလုပ်ခဲ့ပါက ပယ်ဖျက်ရန်အချိန်ပေးသည်။

**ဖျက်ပစ်သည့်အရာများ-**
- သင့်စက်ပစ္စည်းသော့များ (ကုဒ်ဝှက်ထားသောအကြောင်းအရာအားလုံးကို အရန်ကူးများမှပင် အပြီးတိုင်ဖတ်၍မရနိုင်အောင်ဖြစ်စေသည်)
- သင့်အကောင့်မှတ်တမ်း၊ အခန်းကဏ္ဍသတ်မှတ်မှုများနှင့် အလုပ်ချိန်မှတ်တမ်း
- သင့် push အကြောင်းကြားချက် token များ

**သင်ဖန်တီးထားသောကုဒ်ဝှက်ထားသည့်အကြောင်းအရာတွင်ဖြစ်ပျက်သည်**: သင်ရေးသားခဲ့သောမှတ်စုများ၊ စကားဝိုင်းမှတ်တမ်းများနှင့်အစီရင်ခံစာများကို ကျန်ရှိသောခွင့်ပြုထားသောစာဖတ်သူများ (အခြားအက်ဒမင်များ) အတွက်ပြန်လည်ကုဒ်ဝှက်သည်။ သင့်မိတ္တူ၏ကုဒ်ဖော်သော့ကိုဖျက်ဆီးပစ်သည်။ အကြောင်းအရာကိုယ်တိုင်သည် အခြားခွင့်ပြုထားသောကြည့်ရှုသူများအတွက်တည်ရှိနေဆဲဖြစ်သည် — ၎င်းကိုအစုလိုက်မဖျက်ပါ၊ အကြောင်းမှာ ခေါ်ဆိုသူများနှင့်အမှုမှတ်တမ်းသည် hub နှင့်သက်ဆိုင်ပြီး သင်ကိုယ်တိုင်နှင့်မသက်ဆိုင်သောကြောင့်ဖြစ်သည်။

**စာရင်းစစ်မှတ်တမ်းများ**: သင့်စာရင်းစစ်မှတ်တမ်းများကိုကုဒ်ဝှက်ဆိုင်ရာဖျက်ဆီးသည် — အသုံးပြုသူတစ်ဦးချင်းစီအတွက်ကုဒ်ဝှက်သော့ကိုဖျက်ဆီးကာ သင့်မှတ်တမ်းများကိုဖတ်၍မရနိုင်အောင်ဖြစ်စေသည်။ hash ကွင်းဆက် (အနှောင့်အယှက်ရှာဖွေနိုင်သောဖွဲ့စည်းပုံ) သည်နဂိုအတိုင်းရှိနေဆဲဖြစ်သည်။

### အရေးပေါ်ဖျက်ခြင်း

သင့်အကောင့်သည်ချက်ချင်းခြိမ်းခြောက်မှုအောက်ရောက်နေသည်ဟုယုံကြည်ပါက ပူးတွဲအတည်ပြုသူ — အခြားယုံကြည်ရသူတစ်ဦး (အက်ဒမင် သို့မဟုတ် ယုံကြည်ရသောအဆက်အသွယ်) က အရေးတကြီးအခြေအနေကိုလက်မှတ်ရေးထိုးပေးသူ — ဖြင့် အရေးပေါ်ဖျက်ခြင်းကိုတောင်းဆိုနိုင်သည်။ ၎င်းသည်နှောင့်နှေးမှုကိုအနည်းဆုံး ၄ နာရီအထိလျှော့ချပေးသည်။ ၄ နာရီအနိမ့်ဆုံးသည် အကူအညီမရောက်မီ သက်သေအထောက်အထားများကိုအတင်းအဓမ္မဖျက်ခြင်းမှကာကွယ်ရန်ဖြစ်သည်။

### ဖျက်၍မရသောအရာများ

ခေါ်ဆိုမှုမက်တာဒေတာ (မည်သူဖြေကြားသည်၊ ဘယ်အချိန်၊ ဘယ်လောက်ကြာ) သည် hub ၏စာရင်းစစ်မှတ်တမ်း၏အစိတ်အပိုင်းဖြစ်သည်။ သင့် hub အက်ဒမင်က၎င်းကိုမည်မျှကြာထိန်းသိမ်းရမည်ကိုထိန်းချုပ်သည်။ GDPR အောက်တွင် သင်သည်ပြင်ဆင်ခြင်းသို့မဟုတ်ဖျက်ခြင်းကိုတောင်းဆိုပိုင်ခွင့်ရှိသည် — သင့် hub အက်ဒမင်ကိုဆက်သွယ်ပါ။

---

## ပြန်လည်ရယူရေးအဖွဲ့များ

သင့်စက်ပစ္စည်းအားလုံးဆုံးရှုံးပါက (ဖုန်းပျက်စီး၊ လက်တော့ပ်ခိုးယူခံရ၊ အားလုံး) သင်သည်ပုံမှန်အားဖြင့်သင့်ကုဒ်ဝှက်ထားသောဒေတာအားလုံးကိုဝင်ရောက်ခွင့်ဆုံးရှုံးမည်ဖြစ်သည်။ ပြန်လည်ရယူရေးအဖွဲ့များက၎င်းကိုဖြေရှင်းသည်။

### ပြန်လည်ရယူရေးမည်သို့အလုပ်လုပ်သည်

သင်သည်ယုံကြည်ရသောအဆက်အသွယ်အဖွဲ့တစ်ဖွဲ့ (ပုံမှန်အားဖြင့် ၃-၅ ယောက်) ကိုသင့်ပြန်လည်ရယူရေးအဖွဲ့အဖြစ်သတ်မှတ်သည်။ အဆက်အသွယ်တစ်ဦးစီသည် ပြန်လည်ရယူရေးသော့၏ "မျှဝေမှု" တစ်ခု — ပဟေဠိတစ်ပိုင်း — ကိုကိုင်ဆောင်ထားသည်။

**သင့်အကောင့်ကိုပြန်လည်ရယူရန်-**
၁။ သင်သည်စက်ပစ္စည်းအသစ်တစ်ခုမှတ်ပုံတင်ပြီး ပြန်လည်ရယူရေးတောင်းဆိုချက်ကိုစတင်သည်
၂။ သင့်ပြန်လည်ရယူရေးအဆက်အသွယ်များတစ်ဦးစီသည် အကြောင်းကြားချက်တစ်ခုရရှိသည်
၃။ ဖွဲ့စည်းနိုင်သောနှောင့်နှေးမှုတစ်ခုပြီးနောက် (အတင်းအကျပ်တောင်းဆိုချက်ကိုပယ်ဖျက်ရန်အချိန်ပေးရန်) အဆက်အသွယ်များ၏အဆင့်သတ်မှတ်ချက်တစ်ခု (ဥပမာ၊ ၃ ယောက်တွင် ၂ ယောက်) ကတောင်းဆိုချက်ကိုအတည်ပြုသည်
၄။ အတည်ပြုသောအဆက်အသွယ်တစ်ဦးစီသည် ၎င်းတို့၏မျှဝေမှုကိုပို့သည်၊ သင့်စက်ပစ္စည်းအသစ်သို့တိုက်ရိုက်ကုဒ်ဝှက်ထားသည်
၅။ သင့်စက်ပစ္စည်းအသစ်သည် မျှဝေမှုများကိုပေါင်းစပ်၍ ပြန်လည်ရယူရေးသော့ကိုပြန်လည်တည်ဆောက်ကာ သင့်ကုဒ်ဝှက်ထားသောဒေတာသို့ဝင်ရောက်ခွင့်ကိုပြန်လည်ရရှိသည်

**ဆာဗာမြင်နိုင်သည့်အရာ**: ဆာဗာသည် စက်ပစ္စည်းများအကြားကုဒ်ဝှက်ထားသောမျှဝေမှုအပိုင်းအစများကိုထပ်ဆင့်ပို့သည်။ ၎င်းသည်မျှဝေမှုများကိုဖတ်၍မရပါ၊ ပြန်လည်ရယူရေးသော့ကိုသူ့ဘာသာပြန်လည်တည်ဆောက်၍မရပါ၊ နှင့် အဆင့်သတ်မှတ်ချက်လိုအပ်ချက်ကိုကျော်ဖြတ်၍မရပါ။

### ပြန်လည်ရယူရေးအဖွဲ့များ၏လုံခြုံရေးဂုဏ်သတ္တိများ

- **အဆင့်သတ်မှတ်ချက်လုံခြုံရေး**: အဆင့်သတ်မှတ်ချက်အောက်ရှိမျှဝေမှုများသည်လျှို့ဝှက်ချက်အကြောင်းဘာမှမဖော်ပြပါ — မျှဝေကိုင်ဆောင်သူတစ်ဦးတည်းသည်သင့်အကောင့်ကိုတစ်ဦးတည်းပြန်လည်မရယူနိုင်ပါ
- **လျှို့ဝှက်ချက်တွင်ဆာဗာပါဝင်မှုမရှိ**: မျှဝေမှုများကိုသင့်စက်ပစ္စည်းအသစ်၏အများသုံးသော့သို့တိုက်ရိုက်ကုဒ်ဝှက်ထားသည်; ဆာဗာသည် ciphertext ကိုသာသိမ်းဆည်းပြီးထပ်ဆင့်ပို့သည်
- **Hub အလိုက်နယ်ပယ်**: ပြန်လည်ရယူရေးသည်သတ်မှတ် hub တစ်ခုအတွက်သင့်ဝင်ရောက်ခွင့်ကိုပြန်လည်ရရှိစေသည်။ သင်သည် hubs အများအပြားတွင်ရှိပါက hub တစ်ခုစီတွင်၎င်း၏ကိုယ်ပိုင်ပြန်လည်ရယူရေးအဖွဲ့ရှိသည်
- **ပယ်ဖျက်နိုင်သောနှောင့်နှေးမှု**: နှောင့်နှေးကာလအတွင်းသင်သည်ပြန်လည်ရယူရေးတောင်းဆိုချက်ကိုပယ်ဖျက်နိုင်သည် — သင့်ကိုယ်စားတစ်စုံတစ်ယောက်ကသင့်အသိပညာမပါဘဲပြန်လည်ရယူရေးတောင်းဆိုချက်ကိုစတင်ခြင်းမှကာကွယ်ရန်
- **Signal အတည်ပြုချက်**: ပြန်လည်ရယူရေးတောင်းဆိုချက်များကို Signal မှတစ်ဆင့်အတည်ပြုပြီး သင်သည်သင့်အထောက်အထားနှင့်ဆက်စပ်နေသော Signal အကောင့်ကိုထိန်းချုပ်ကြောင်းအတည်ပြုသည်

### ပြန်လည်ရယူရေးအဆက်အသွယ်များရွေးချယ်ခြင်း

သင်ယုံကြည်သောသူများကိုရွေးချယ်ပါ-
- လွတ်လပ်စွာဆက်သွယ်၍ရနိုင်သူများ (တစ်နေရာတည်းသို့မဟုတ်အဖွဲ့အစည်းတစ်ခုတည်းတွင်အားလုံးမဟုတ်ပါ)
- ၎င်းတို့ကိုယ်တိုင် Signal ကိုအသုံးပြုသူများ (အတည်ပြုခြင်းအဆင့်အတွက်လိုအပ်)
- ၎င်းတို့သည်ရံဖန်ရံခါပြန်လည်ရယူရေးတောင်းဆိုချက်များကိုအတည်ပြုရန်တောင်းဆိုခံရမည်ကိုနားလည်သူများ

သင့်ပြန်လည်ရယူရေးအဆက်အသွယ်များသည်မျှဝေမှုတစ်ခုကိုကိုင်ဆောင်ထားခြင်းဖြင့်သင့်ကုဒ်ဝှက်ထားသောဒေတာသို့ဝင်ရောက်ခွင့်မရရှိပါ — သင်တောင်းဆိုချက်တစ်ခုစတင်မှသာ ၎င်းတို့သည်သင့်အားပြန်လည်ရယူရန်ကူညီနိုင်သည်။

## စေတနာ့ဝန်ထမ်းဖုန်းနံပါတ်ကိုယ်ရေးလုံခြုံမှု

စေတနာ့ဝန်ထမ်းများသည်၎င်းတို့၏ကိုယ်ပိုင်ဖုန်းများသို့ခေါ်ဆိုမှုများလက်ခံရရှိသောအခါ ၎င်းတို့၏နံပါတ်များသည်သင့်တယ်လီဖုန်းဝန်ဆောင်မှုပေးသူအားထုတ်ဖော်ပြသခံရသည်။

| အခြေအနေ | ဖုန်းနံပါတ်ကိုမြင်နိုင်သူ |
|---|---|
| စေတနာ့ဝန်ထမ်း၏ဖုန်းသို့ PSTN ခေါ်ဆိုမှု | တယ်လီဖုန်းဝန်ဆောင်မှုပေးသူ၊ ဖုန်းကုမ္ပဏီ |
| ဘရောက်ဆာမှဘရောက်ဆာ (WebRTC) | မည်သူမျှမ (အသံသည်ဘရောက်ဆာတွင်ရှိနေ) |
| ကိုယ်တိုင်လက်ခံဆောင်ရွက်ထားသော Asterisk + SIP ဖုန်း | သင့် Asterisk ဆာဗာသာ |

**စေတနာ့ဝန်ထမ်းဖုန်းနံပါတ်များကိုကာကွယ်ရန်**: ဘရောက်ဆာအခြေပြုခေါ်ဆိုမှု (WebRTC) ကိုသုံးပါ သို့မဟုတ် ကိုယ်တိုင်လက်ခံဆောင်ရွက်ထားသော Asterisk သို့ချိတ်ဆက်ထားသော SIP ဖုန်းများကိုထောက်ပံ့ပါ။

| ဖျက်ချိန်တွင်ကုဒ်ဝှက်ဆိုင်ရာဖျက်ဆီးခြင်း | သင့်ကုဒ်ဝှက်သော့များကိုဦးစွာဖျက်ဆီးကာ ဒေတာဘေ့စ်ဖျက်ခြင်းမပြုမီအကြောင်းအရာကိုအပြီးတိုင်ဖတ်၍မရနိုင်အောင်ဖြစ်စေသည် |
| ပြန်လည်ရယူရေးအဖွဲ့များ (Shamir) | စက်ပစ္စည်းအားလုံးဆုံးရှုံးပါကကူညီနိုင်သောယုံကြည်ရသည့်အဆက်အသွယ်များကိုသတ်မှတ်နိုင် — အဆင့်သတ်မှတ်ချက်အောက်မျှဝေမှုများသည်ဘာမှမဖော်ပြ |
| ရိုးသားစွာထုတ်ဖော်မှုပါသောထုတ်လွှင့်မက်ဆေ့ချ်ပို့ခြင်း | အက်ဒမင်များသည်အစုလိုက်မက်ဆေ့ချ်များကိုပို့နိုင်; ဆာဗာသည်ပို့ဆောင်ရန်အတွက်ရိုးရိုးစာသားကိုခဏတာလုပ်ဆောင် (UI တွင်ရှင်းလင်းစွာထုတ်ဖော်ထား) |
| စာရင်းသွင်းသူ hashing | ထုတ်လွှင့်စာရင်းသွင်းသူဖုန်းနံပါတ်များကို hash လုပ်ထားသောအညွှန်းများအဖြစ်သိမ်းဆည်း — ဒေတာဘေ့စ်တွင်ရိုးရိုးစာသားစာရင်းသွင်းသူစာရင်းမရှိ |
| Argon2id သော့ကာကွယ်ရေး | သင့်စက်ပစ္စည်းသော့များကို GPU များနှင့်အထူးပြုဟာ့ဒ်ဝဲဖြင့် brute-force တိုက်ခိုက်မှုများကိုခံနိုင်ရည်ရှိသောမှတ်ဉာဏ်ခိုင်မာသည့်လုပ်ဆောင်ချက်ဖြင့်ကာကွယ်ထား |
| Signal-ဦးစားပေးမက်ဆေ့ချ်လမ်းကြောင်းသတ်မှတ်ခြင်း | ရရှိနိုင်ပါကမက်ဆေ့ချ်များကို Signal မှတစ်ဆင့်အလိုအလျောက်လမ်းကြောင်းသတ်မှတ်ကာ SMS ဝန်ဆောင်မှုပေးသူမှတ်တမ်းများတွင်အကြောင်းအရာမပါဝင်စေရန်ကာကွယ် |
| SMS အကြောင်းကြားချက်သာ mode | SMS လက်ခံသူများသည် "သင့်တွင်မက်ဆေ့ချ်အသစ်ရှိသည်" ကိုသာမြင် — ဝန်ဆောင်မှုပေးသူမှတ်တမ်းများတွင်ထိလွယ်ရှလွယ်အကြောင်းအရာမရှိ |
| အသွားအလာခွဲခြမ်းစိတ်ဖြာမှုခံနိုင်ရည် | အချိန်နှင့်တပြေးညီဖြစ်ရပ်အရွယ်အစားများကိုဖြည့်စွက်ထားသောကြောင့် စောင့်ကြည့်သူများသည်တိုတောင်းသောမက်ဆေ့ချ်များနှင့်ရှည်လျားသောမက်ဆေ့ချ်များကိုခွဲခြား၍မရ |
| ဒေတာဘေ့စ်တွင်ရိုးရိုးစာသားဖုန်းနံပါတ်များမရှိ | ခေါ်ဆိုသူနံပါတ်များကိုနောက်ပြန်မဆုတ်နိုင်သော hashes အဖြစ်သိမ်းဆည်း — သင့်ဒေတာဘေ့စ်တွင်အမှန်တကယ်ဖုန်းနံပါတ်ဘယ်တော့မျှမပါဝင် |
| ရှေ့သွားလျှို့ဝှက်မှုပါသော Hub အလိုက်ကုဒ်ဝှက်ခြင်း | hub တစ်ခုစီ၏အချိန်နှင့်တပြေးညီဖြစ်ရပ်များကို ၂၄ နာရီတိုင်းလှည့်ပြောင်းသောသော့များဖြင့်ကုဒ်ဝှက်ထား — သော့ဟောင်းများသည်ဖြစ်ရပ်အသစ်များကိုမကုဒ်ဖော်နိုင် |
