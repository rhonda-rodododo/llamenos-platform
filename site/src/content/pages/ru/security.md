## Если ваш хостинг-провайдер получит повестку

| Они МОГУТ предоставить | Они НЕ МОГУТ предоставить |
|------------------------|--------------------------|
| Метаданные звонков/сообщений (время, продолжительность) | Содержание заметок, транскрипций, отчётов |
| Зашифрованные данные из базы данных | Имена волонтёров (шифрование конец-конец) |
| Какие аккаунты волонтёров были активны и когда | Записи каталога контактов (шифрование конец-конец) |
| Записи о доставке массовых сообщений | Содержание сообщений (шифруется при получении, хранится как шифротекст) |
| | Ключи расшифровки (защищены PIN-кодом, провайдером идентификации и опционально аппаратным ключом безопасности) |
| | Ключи шифрования на заметку (эфемерные — уничтожаются после упаковки) |
| | Ваш секрет HMAC для обращения хешей телефонных номеров |
| | Содержание фрагментов восстановления (зашифровано, сервер не может читать) |

**Сервер хранит данные, которые не может читать.** Метаданные (когда, как долго, какие аккаунты) видны. Содержание (что было сказано, написано, кто ваши контакты) — нет.

## По функциям

Ваша уязвимость для слежки зависит от того, какие каналы вы активируете:

### Голосовые звонки

| Если вы используете... | Третьи стороны могут получить | Сервер может получить | Содержимое с шифрованием конец-конец |
|------------------------|------------------------------|----------------------|--------------------------------------|
| Twilio/SignalWire/Vonage/Plivo | Аудио звонка (в реальном времени), записи | Метаданные звонка | Заметки, транскрипции |
| Самостоятельно размещённый Asterisk | Ничего (вы контролируете) | Метаданные звонка | Заметки, транскрипции |
| Браузер к браузеру (WebRTC) | Ничего | Метаданные звонка | Заметки, транскрипции |

**Повестка провайдеру телефонии**: У них есть детальные записи звонков (время, номера, продолжительность). У них НЕТ заметок или транскрипций. Запись по умолчанию отключена.

**Транскрипция**: Транскрипция происходит полностью в вашем браузере с помощью локального ИИ. **Аудио никогда не покидает ваше устройство.**

### Текстовые сообщения (один на один)

| Канал | Доступ провайдера | Хранение на сервере | Примечания |
|-------|------------------|--------------------|-----------| 
| SMS | Ваш провайдер телефонии читает все сообщения | **Зашифровано** | Провайдер сохраняет оригинальные сообщения |
| WhatsApp | Meta читает все сообщения | **Зашифровано** | Провайдер сохраняет оригинальные сообщения |
| Signal | Сеть Signal использует E2EE; мост повторно шифрует при получении | **Зашифровано** | Предпочтительный маршрут при наличии |

**Маршрутизация с приоритетом Signal**: Когда у получателя есть Signal, сообщения автоматически маршрутизируются через Signal. Для SMS по умолчанию отправляется только общее уведомление (без текста сообщения).

**Сообщения шифруются в момент поступления на ваш сервер.** Сервер хранит только шифротекст.

### Массовые рассылки и трансляции

Администраторы могут отправлять массовые сообщения подписчикам через SMS, WhatsApp, Signal или RCS.

**Важно: исходящие массовые сообщения НЕ зашифрованы конец-конец на сервере.** Для доставки сообщения подписчикам SMS или WhatsApp сервер должен кратковременно обработать содержание в открытом виде и передать его провайдеру сообщений.

| Канал | Доступ сервера при отправке | Доступ провайдера | После доставки |
|-------|---------------------------|------------------|----------------|
| SMS-рассылка | Открытый текст (кратковременно, для доставки) | Полное содержание | Провайдер сохраняет |
| WhatsApp-рассылка | Открытый текст (кратковременно, для доставки) | Полное содержание (Meta) | Провайдер сохраняет |
| Signal-рассылка | Открытый текст (кратковременно, для доставки) | Зашифровано E2EE через сеть Signal | Провайдер не сохраняет |
| RCS-рассылка | Открытый текст (кратковременно, для доставки) | Google может видеть содержание | Провайдер сохраняет |

**Что это означает**: Массовые сообщения не должны содержать конфиденциальную информацию об абонентах. Используйте их для объявлений и уведомлений — не для деталей дел.

Телефонные номера подписчиков хранятся как хешированные идентификаторы — ваша база данных никогда не содержит список подписчиков в открытом виде.

### Заметки, транскрипции и отчёты

Всё содержание, написанное волонтёрами, зашифровано конец-конец:

- Каждая заметка использует **уникальный случайный ключ** (прямая секретность — компрометация одной заметки не затрагивает другие)
- Ключи упакованы отдельно для волонтёра и каждого администратора
- Сервер хранит только шифротекст
- Расшифровка происходит на вашем устройстве в защищённом слое, который никогда не раскрывает ключи интерфейсу приложения
- **Пользовательские поля, содержание отчётов и вложения шифруются по отдельности**

**Записи дел и данные сущностей**: Следуют той же модели шифрования — каждый элемент зашифрован с уникальным ключом.

**Изъятие устройства**: Без вашего PIN-кода **и** доступа к вашему аккаунту провайдера идентификации злоумышленники получают зашифрованный блоб, защищённый Argon2id. С аппаратным ключом безопасности **три независимых фактора** защищают ваши данные.

## Ваши устройства

### Просмотр и отзыв устройств

Приложение ведёт список каждого устройства, с которого вы входили. Вы можете просмотреть этот список и отозвать любое устройство, которое не узнаёте.

**При отзыве устройства:**
- Это устройство немедленно блокируется от доступа к вашему аккаунту
- Ваши ключи шифрования ротируются, чтобы отозванное устройство не могло расшифровать будущий контент
- Отзыв фиксируется в истории безопасности вашего аккаунта

### Верификация SAS-эмодзи

Для организаций с высокими требованиями к безопасности администраторы могут верифицировать личность устройства с помощью верификации SAS (Short Authentication String) — отображается как последовательность из 7 эмодзи.

**Как это работает:**
1. Администратор и владелец устройства сравнивают свои последовательности эмодзи (лично, по телефону или через доверенный канал)
2. Если эмодзи совпадают, устройство подтверждается как принадлежащее его зарегистрированному владельцу
3. Верификация фиксируется — администраторы могут видеть, какие устройства были верифицированы

Это защищает от злоумышленника, который зарегистрировал поддельное устройство под чужим аккаунтом.

## Удаление аккаунта

### Удаление по инициативе пользователя

Вы можете запросить постоянное удаление вашего аккаунта и всех связанных данных. По умолчанию есть задержка (настраивается администратором хаба, обычно 72 часа) перед завершением удаления — это даёт вам время отменить запрос, если он был сделан под принуждением.

**Что удаляется:**
- Ваши ключи устройства (делая весь зашифрованный контент безвозвратно нечитаемым, даже из резервных копий)
- Запись вашего аккаунта, назначения ролей и история дежурств
- Ваши токены push-уведомлений

**Что происходит с созданным вами зашифрованным контентом**: Заметки и отчёты, которые вы написали, повторно шифруются для оставшихся авторизованных читателей. Ваша копия ключа расшифровки уничтожается.

**Журналы аудита**: Ваши записи журнала аудита «крипто-уничтожаются» — ключ шифрования пользователя уничтожается, делая ваши записи нечитаемыми. Хеш-цепочка остаётся нетронутой.

### Экстренное удаление

Если вы считаете, что ваш аккаунт находится под непосредственной угрозой, вы можете запросить экстренное удаление с соавтором — сокращает задержку до минимум 4 часов. Минимум 4 часа существует для защиты от принудительного удаления.

## Группы восстановления

Если вы потеряете все свои устройства, вы обычно потеряете доступ ко всем зашифрованным данным. Группы восстановления решают эту проблему.

### Как работает восстановление

Вы назначаете группу доверенных контактов (обычно 3-5 человек) в качестве вашей группы восстановления. Каждый контакт держит один «фрагмент» ключа восстановления.

**Для восстановления вашего аккаунта:**
1. Вы регистрируете новое устройство и инициируете запрос на восстановление
2. Ваши контакты восстановления получают уведомление
3. После настраиваемой задержки пороговое количество контактов (например, 2 из 3) одобряют запрос
4. Каждый одобряющий контакт отправляет свой фрагмент, зашифрованный прямо на ваше новое устройство
5. Ваше новое устройство объединяет фрагменты для восстановления ключа

**Что может видеть сервер**: Сервер передаёт зашифрованные фрагменты между устройствами. Он не может читать фрагменты и не может самостоятельно восстановить ключ.

### Свойства безопасности групп восстановления

- **Пороговая безопасность**: Фрагменты ниже порога не раскрывают ничего о секрете
- **Сервер не участвует в секрете**: Фрагменты шифруются прямо на открытый ключ вашего нового устройства
- **Область хаба**: Восстановление возобновляет ваш доступ к конкретному хабу
- **Задержка с возможностью отмены**: Вы можете отменить запрос на восстановление в период задержки
- **Верификация через Signal**: Запросы на восстановление верифицируются через Signal

## Конфиденциальность телефонных номеров волонтёров

Когда волонтёры принимают звонки на личные телефоны, их номера становятся видны вашему провайдеру телефонии.

| Сценарий | Телефонный номер виден |
|----------|----------------------|
| PSTN-звонок на телефон волонтёра | Провайдеру телефонии, мобильному оператору |
| Браузер к браузеру (WebRTC) | Никому (аудио остаётся в браузере) |
| Самостоятельно размещённый Asterisk + SIP-телефон | Только вашему серверу Asterisk |

**Для защиты номеров волонтёров**: Используйте браузерные звонки (WebRTC) или предоставьте SIP-телефоны, подключённые к самостоятельно размещённому Asterisk.
